# 分域做法：通用工程实践（做产品时该想到的事）

> **不是协作规矩**（那些在 `ai/rules/`），是**做产品时该想到的事**。按需查，不进开场必读。
> 每条都来自**真实付过代价**的场景，已去掉来源项目的痕迹。

## 一、不可逆与回滚

| 做法 | 为什么 |
|---|---|
| **不可逆动作之前，把只读检查全部做完**（空间、权限、依赖、目标是否被占用） | 做到一半才发现装不下，已经删掉的东西回不来 |
| **认不出来就按「拦住」处理**（fail-closed） | 识别失败时放行，等于把最不确定的情况按最宽松的处理 |
| **留反悔余地**：危险动作给一个「确认—自动回滚」的计时器，人不确认就退回 | 远程改网络/权限时，改错了连改回去的通道都没了 |
| **回滚要恢复「运行状态」，不只是文件** | 文件回去了、服务还开着旧配置，症状比没回滚更怪 |
| **原子替换**：写临时文件 → 改名，不要就地改 | 中途被打断时，要么旧的完整、要么新的完整，不许出现半截 |
| **删目录前先卸挂载** | 挂载点下面是别人的数据，`rm -rf` 会顺着挂载穿过去 |

## 二、时序与等待

| 做法 | 为什么 |
|---|---|
| **等「就绪」这个事实，不等固定秒数** | 睡 3 秒在你机器上够，在慢机器上就是随机失败 |
| **慢活异步 ＋ 超时 ＋ 看门狗**，不要让请求线程干等 | 一个卡住的下游会把整个前端拖成「点了没反应」 |
| **重试要退避**，生成物有上限，外网调用限时 | 没有上限的重试会把偶发故障放大成雪崩 |
| **局部锁死不许拖垮整站**：一个模块坏了，别的还能用 | 共享的全局锁会把单点故障变成全局故障 |
| **状态以服务端为准**，客户端只是显示 | 两边各记一份，迟早不一致，而用户信界面 |
| **瞬态现象要人为拖慢才量得到**（把请求延到 1~2 秒再看） | 快到看不见的中间态，正是 bug 藏身的地方 |

## 三、一致性与去重

| 做法 | 为什么 |
|---|---|
| **一件事一份实现**；改完**全仓搜同形**，别只改撞见的那一处 | 同一个逻辑两份拷贝，修一份就是留一个定时炸弹 |
| **前端不许比后端窄**：后端支持的取值，前端别自己再砍一刀 | 界面上做不到的事，用户会以为系统不支持 |
| **没有稳定 ID 就不要靠文本匹配**去定位对象 | 文案一改，匹配全断，而且没有任何报错 |
| **官方已有的能力优先**，不自己造 | 自己造的那份不会跟着上游修 bug |
| **缓存串用内容指纹**，不要手写版本号 | 「改了没效果」这一类，人记不住同时改两处 |
| **缓存只替代下载，不替代校验** | 命中缓存跳过校验，坏的那份会一直被复用 |

## 四、交付与发行

| 做法 | 为什么 |
|---|---|
| **构建对账**：交付物的指纹必须等于从源码重新构建出来的指纹 | 否则「改了没写回」「写回了没构建」都看不出来 |
| **发行版不带调试口** | 调试口是按「只有我能连」设计的，发出去就不是了 |
| **修了没推等于没修**；推完要有一条能验证「跑的就是新的」的判据 | 真机上跑的还是旧的，而所有测试都在新的上过 |
| **首次路径单独验**（第一次安装、第一次启动、空数据） | 老环境跑得好好的，新用户第一步就撞墙 |
| **升级路径与老数据单独验** | 新装能用不等于升级能用 |
| **核心链路每轮真跑一次**，不靠单测推断 | 单测只测纯函数等于没测 |
| **跨平台差异先想清楚**（路径、大小写、换行、权限位） | 换一台机器就红的东西，大多是这四样 |

## 五、安全与边界

| 做法 | 为什么 |
|---|---|
| **秘密不落明文**；日志、报错、前端都不许带 | 一次截图就外泄了 |
| **安全例外要有前提**（谁、在什么条件下、到期怎么办） | 没有到期条件的例外，就是永久的洞 |
| **信任边界按「监听面」划**，不按目录结构 | 真正决定谁能进来的是端口和接口，不是代码在哪个文件夹 |
| **先可行性再界面**：没验证过能做到的事，不要先把按钮画出来 | 按钮画出来之后，砍掉的成本就变成了「需求方觉得你砍功能」 |
