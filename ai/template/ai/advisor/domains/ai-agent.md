# 分域做法：AI 助手与 agent

| 维度 | 做法 | 为什么 |
|---|---|---|
| 助手是模块 | 系统助手和 agent 引擎是一个**可替换的应用 / 模块**，不是写死在系统里 | 模型和 agent 框架变得太快 |
| AI 底座归系统 | 系统的 AI 设置只管：模型、按分类索引的 skills / MCP（应用注册的技能即作为实现，可被替代）、安装外部 skills / MCP、知识库、公共目录、用量 | 多个 AI 应用共用一份底座，不各配一遍 |
| AI 是主体 | 独立身份，**不默认继承人的全部权限**；有效权限 = AI 自己 ∩ 它代表的人；三档：**读给它 · 写要问 · 危险只能提议**，人批准后以人的身份执行，审计记「由 AI 发起」；靠 OS 边界（独立账号 + 沙箱）拦，不靠判断命令文本 | 判断命令文本总能被绕过；OS 边界不能 |
| 自我进化 | 信号 → 反思 → 提议 → 评测 → 采纳 → 观察 → 回退；🔴 **只进化数据（记忆、技能、提示词、规则、流程），不进化权限、系统配置、裁判、审计**；按真实结果判进步；真实任务存成评测用例 | 进化了裁判就等于没有裁判 |
| 编排 | 声明式流程文件，运行起来是任务中心的父子任务；**子 agent 权限只能收窄**；多种 agent 设计（ReAct / 规划-执行-检查 / 状态机 / 黑板）做成插件，工具调用、预算、取消、事件流、运行记录由框架统一 | 换 agent 设计不换基础设施 |
| 小模型 | 训练或封装小模型给大模型调用（像目标检测模型那样封成技能） | 便宜、快、可离线 |
| 决策模型 | 「只判断不生成」的小模型用于意图路由、工具选择、是否升级到大模型 | 提速、降 token |
| 浏览器操控 | agent 通过受控浏览器把「没有 API 的一切」变成可调用能力；适配器可换；许可证不明的先确认 | 大量真实服务没有 API |
| 本地模型 | 自己管理，不依赖单一工具；显存预算规划 + 省内存 / 平衡 / 快三档，分清「真省」与「拿速度换」 | 用户硬件差异极大 |
| 模型网关 | 多模型按能力路由，可设默认、可关，用量可见 | 模型是可替换的基础设施 |
| AI 用得上 | 工具返回能表达「我不确定」；诊断码、自检命令；说明按需检索、带版本、英文 | AI 最怕的是假装确定 |
| 随身的助手 | 手机 / 平板 / 电脑远程和同一个助手对话（同一份记忆、权限、审计）；在外面派活、到家做完；多用户各有各的 AI 身份；AI 伴侣：记得你、一直在线、真的能动手、干完留痕；语音终端 | 助手的价值在「随时随地、同一个」 |
| 关掉仍可用 | 关掉 AI，产品照样完整可用 | AI 是增强，不是依赖 |
