# 联想链：说到 A，就该同时想到 B

> 需求方常常一条一条补。**他说一句，你该推得出三句**——但一次最多提两三条，每条写好处与代价，按推荐排序。

| 说到 | 同时提出 |
|---|---|
| 支持多个框架 | 契约去框架化；每个框架的 SSR 方案；脚手架按框架过滤；文档按框架分页签；一份测试多框架共跑 |
| 适配第三方库 | 只认官方出品吗？同时支持几个框架就都适配？映射不到的缺口表；退回自研；库的语种与主题同步 |
| 做脚手架 | TS / JS；构建工具矩阵；非交互参数（给 AI）；脚手架本身的文档与 AI 条目 |
| 按需引入 | 兼容表与版本范围；体积预算；可选能力隔离 |
| 给 AI 用 | 不灌上下文、分层检索；skill / MCP / CLI 都要且同源；版本号；诊断码与自检命令；AI 评测进验收；条目用英文 |
| 文档 | 总览页、在线案例、API 表由契约生成；多语言；大版本并存 |
| 国际化 | 界面文案 / 人看文档 / AI 条目三件分开定；宿主 i18n 怎么整合；日期数字格式化；RTL；SSR 首屏先载语言包 |
| 主题 / 风格 | 运行时改几个颜色；只改某个组件；基于内置风格再覆盖；局部嵌套换风格；高对比与无障碍 |
| 做组件 | 逐项完成清单；清单加步骤时旧组件怎么回补；复杂组件先做以验证引擎 |
| 用最新版 | 运行时（Node / Go）也要最新；实现时读该版本官方文档；兼容表写实测版本 |
| 任何「逐步做」的事 | 写进每条任务的完成定义；里程碑末统一梳理一次 |
| 新产品线 / 新系统 | 满血与轻量两个形态共用什么；客户端连多台设备；云端控制面与数据面；授权激活；错误收集回流开发队列 |
| 插件 / 应用 | core + profile 协议；投影与扩展槽；功能与互斥；缺席态；签名审核；商店与付费；无代码资源包 |
| AI 助手 | 做成可替换的模块；AI 底座（模型、技能、知识库、用量）归系统；三档权限与「提议」；手机远程对话；多用户各自的 AI 身份；记忆；语音 |
| agent | 进化边界（只进化数据，不进化权限与裁判）；评测集与回退；编排与子 agent 权限只能收窄；小型决策模型提速降 token；浏览器操控 |
| 本地模型 | 自托管、不绑单一工具；显存 / 内存预算与分档；多模型按能力路由；用量可见 |
| 对外服务 / 远程 | 数据不经过我们；公网暴露只能管理员部署后打开；独立令牌；兜底中继限流 |
| 开源 / 闭源 | 公开面门禁；许可证白名单；机密不进公开仓库 |
| 起名 / 改名 | 撞命令、撞公司、商标、包名、域名；仓库名 ≠ 品牌；批量改名别误伤包含该字母串的其他词 |
| 兼容现有 | 数据迁移工具；旧接口承诺期；旧客户端怎么提示升级；导入导出格式 |
| 对外材料 | 同源多格式（md / 网页 / PPT / PDF）；logo 与图标用现成的；不写没做的、不放无来源数字 |
| 新席位 / 新流程 | 所有按席位列举的守门（目录归属表、信箱、预算、README）都要一起改——加席位 ≠ 加手册 |
