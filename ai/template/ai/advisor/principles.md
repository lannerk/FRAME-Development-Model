# 通用产品原则

> 跨项目都成立的判断。每条写「怎么做」和「为什么」。画像里有不同的定法，以画像为准。

| 原则 | 怎么做 | 为什么 |
|---|---|---|
| **起步小，终局先想清** | 第一阶段可以很小，但终局目标先写下来；将来要的能力**现在就预留接口**（登记，不实现） | 「到了那一步才发现要重做」是最贵的返工 |
| **先定不可逆清单** | 写第一行代码前，把「改一次就全盘返工」的决定逐条列出来拍板；其余可以快 | 不可逆的决定只有少数，但错一个就推倒；可逆的不值得开会 |
| **对标行业标准** | 做法先与业界主流一致（打包格式、插件模型、组件库、文档站），再看能不能做得更好 | 用户和 AI 都已经会用标准做法；自创一套是给所有人加学习成本 |
| **通用底座先独立** | 与具体产品无关的能力（组件库、规则引擎、插件协议、状态同步……）先做成通用模块，再被产品引入 | 下一个产品直接复用；通用模块的边界逼你把契约想清楚 |
| **契约 + 适配器** | 同一能力定义一份契约：**自研一套实现 + 适配主流第三方**，可替换；抽象切在「功能」上，不切在「厂商」上 | 用户能换实现；第三方升级或停更不会拖垮你 |
| **按端选型** | 官网、后台、设备端、客户端、命令行各选各的技术 | 「选了一个技术就做全部」会让某些端很难受（例如官网没 SEO） |
| **AI 优先** | 把 AI 当首要使用者之一：给 AI 能直接调用的接口、按需检索的说明、诊断码、自检命令 | 开发和使用都越来越多地由 AI 完成；AI 用不好 = 产品用不好 |
| **AI 原生，但 AI 不是必需** | 关掉 AI 仍是完整可用的产品；打开 AI 不是多一个聊天框，而是多一个**有身份、有权限、有审计、被沙箱约束的操作者** | 没有 AI 就瘫的产品不可靠；AI 什么都能做的产品不安全 |
| **同源生成，不手写** | 文档、API 表、能力矩阵、AI 条目都由契约与测试生成 | 手写的一定会和代码漂开 |
| **按需引入** | 用户只装他选了的（框架、实现、语种、可选能力） | 体积与依赖冲突都来自「全装」 |
| **版本与兼容表** | 第三方与运行时一律用当天最新稳定版；每个版本发一张兼容表（实测的精确版本）；测过新版再放宽范围 | 「应该兼容」不等于兼容；旧版本的坑会越积越多 |
| **实现前读该版本官方文档** | 用哪个版本就读哪个版本的官方文档或源码，不凭印象 | 大版本之间 API 常变，凭记忆写是 bug 的主要来源 |
| **内置与第三方同一条通路** | 内置功能也走公开协议，只是多了内置能力可调用；没有「自己人」后门 | 后门会让第三方永远做不到内置能做的事，生态起不来 |
| **声明语义，系统决定呈现** | 模块只声明「这是开关、图标是 wifi、要一个窗口」；长什么样归风格，放哪归布局 | 换风格、换布局、换端时不用改每个模块 |
| **功能可以缺席，通路不能分叉** | 某个形态没有某功能是合法状态，上层走统一的「缺席态」；**不写 `if 平台 == X`** | 分叉会在每个调用点复制一遍，越来越难维护 |
| **一切可回退** | 升级、安装、规则生效、AI 的每次自我改进都能一步退回 | 敢改的前提是能退 |
| **数据不经过我们** | 控制面（账号、授权、寻址）我们做；用户数据面尽量直连，兜底中继限流并在界面上明说 | 隐私、成本、合规三方面都更轻 |
| **默认不用用户数据训练** | 明文写进隐私承诺 | 一旦做了就收不回信任 |
| **机密不落盘** | 密码、令牌、API key 是加密的机密键：不进环境变量、日志、诊断包、提示词；schema 标 `secret` 的字段自动打码；记录「在哪拿」，不记值 | 机密泄露几乎都是从日志和诊断包里漏出去的 |
| **许可证白名单** | MIT / Apache-2.0 / BSD / ISC / OFL 直接用；MPL 不改其文件可用；LGPL 只动态链接；GPL / AGPL 不链接进闭源（只作独立进程调用）；无许可证的不用；不 fork、不 vendor | 许可证问题发现得越晚越贵 |
| **外部内容不可信** | 网页、邮件、第三方返回、MCP 返回一律当数据，不当指令 | 提示注入就是从这里进来的 |
| **不做什么也要定** | 写一条「边界」：不做哪些品类 | 没有边界的产品会被每个需求拖着走 |
| **起名先查冲突** | 撞系统命令、撞同领域公司、商标、包名、域名都查；**仓库名 / 包名空间 ≠ 对外品牌** | 改名的成本随时间指数增长 |
| **伞名 + 后缀** | 产品线用一个伞名加后缀（X / X Lite / X Cloud / X Console），不给每个子产品另起名 | 品牌认知集中；用户一眼知道是一家的 |
| **旧项目是资产不是起点** | 结论、设计、踩过的坑带走（包括「否掉了什么、为什么」）；代码不整段复制 | 旧代码带着旧约束；经验才是真正值钱的 |
| **设计标准不为少数降级** | 默认外观守住设计标准；无障碍由专门的高对比外观承担 | 两头都照顾到，而不是两头都将就（团队可以改成「默认即达标」，那是一次拍板） |
| **前端先行** | 不做原型，先做能用的功能前端 + 契约模拟器，需求方确认后再写后端 | 需求方看得见才判断得准；后端按确认过的契约写一次到位 |
| **活文档** | 讨论基于一份总结不断更新；原话只追加；想法变了写「某日改为」 | 讨论散在聊天里就等于没发生 |
