# 开场顾问（`ai/advisor/`）

> **谁读这一份**：**任何一席**（四席 ＋ 研究席），在需求方开新项目 / 提新需求 / 问「这个怎么做」的时候。
> 走法写在 `ai/rules/requester.md` §四之四「先替他想，再问他」。
> **这是 FRAME 本体的一部分**（follow 类，随同步更新）。🔴 **里面只许有换个项目也成立的通用判断**——
> 品牌名、产品名、仓库名、人名、私有出处编号一律不许进来（`ops/verify/check-advisor.sh` 会扫）。
> **来源**：真实项目里积累的拍板，**已抽象成通用做法**；那些项目专属的定法留在各自的画像里。

## 这是什么

一个用 FRAME 的人，可能不懂技术，也不知道开一个项目要想哪些事。
**开场顾问让任何一席在他开口的时候，先替他把方案想好**：做法、选型、为什么这样建议、不这样会怎样；
他没提到的维度（国际化、兼容现有系统、机密、AI、许可证……）**主动问**，每个选项写代价、标推荐。

## 什么时候用（五种触发）

| 触发 | 读什么 |
|---|---|
| 开新项目 / 新模块 / 新产品线 | 画像 → `questions.md` 全量挑题 → 相关 `domains/*` 与 `stack.md` |
| 提一个范围较大的需求 | 画像 → `chains.md` 找联想 → 相关 `domains/*` |
| 项目中途冒出一条新要求 | 画像 → `chains.md`（他说了 A，就把 B、C 一起提） |
| 问「这个怎么做」「有什么新做法」 | 画像里的以往定法 → `stack.md` / `domains/*` → 最优解；与以往不同就说为什么 |
| 初始化项目 | 走一遍 `questions.md`，把答案写进空的画像 |

**不整份读**：先读画像（通常一页），再按需查本目录的某一节。**不进开场必读。**

## 两层，优先级固定

| 层 | 在哪 | 归谁 | 开源吗 |
|---|---|---|---|
| **需求方画像** | `product/requirements/requester-profile.md` | 本项目（seed：模板只给空骨架） | ❌ 永不回流 |
| **通用顾问库** | `ai/advisor/`（本目录） | FRAME 本体（follow：随同步更新） | ✅ |

🔴 **画像 > 通用库**。画像里他定过的，**直接用、不再问**，在正文里一句话说明套用了哪几条；
通用库只在画像没写的地方给推荐。**通用库的「推荐」不是默认**——要他拍板的仍然弹窗问。

## 文件

| 文件 | 内容 |
|---|---|
| `principles.md` | 通用产品原则（跨项目都成立的判断） |
| `questions.md` | 开场问题库：每题 = 为什么要问 · 不问会怎样 · 选项与代价 · 没有偏好时的推荐 |
| `chains.md` | 联想链：说到 A，就该同时想到 B |
| `stack.md` | 选型卡：情况 → 推荐 → 为什么 → 什么时候不适用 → 可反悔点 |
| `domains/ui.md` | UI 框架与组件库、系统界面 |
| `domains/platform.md` | 平台 / 操作系统 / 设备类产品 |
| `domains/ecosystem.md` | 应用与插件生态 |
| `domains/ai-agent.md` | AI 助手与 agent |
| `domains/materials.md` | 对外材料（投资人 / 客户） |

## 怎么答（给每一席）

1. **先读画像**；画像空 = 新用户，按「小白模式」答（下条）。
2. **给方案卡**，不给一堆选项：推荐做法 · 为什么 · 代价 · 什么时候不适用 · 可反悔点。
3. **小白模式**：画像空、或他说「我不懂技术」时，每个选项用一句白话说后果（「选这个，以后加英文界面要把所有页面过一遍」），推荐项写「拿不准就选这个」。
4. **技术与架构能自己定的直接定**，写可反悔点；**商业取舍、名字、开不开源、范围与排期、对外怎么说**一律弹窗问，不设默认。
5. **沿 `chains.md` 主动推**，最多两三条，每条写好处与代价。
6. **问完再动手**；他的回答原话进需求记录，**拍板追加进画像**（写日期与出处），重要的记 AD。
