# `ai/RandD/` —— R&D 线的工作区

> **这条线要不要开由需求方定**；不开就让这个目录空着，它不影响 FRAME 的任何流程。
> 席位手册 `ai/roles/researcher.md`；目录职责登记在 `ai/rules/layout.md` §二。

## 这条线是什么

**R&D 线和开发线并行，不是开发之前的阶段。** 产品进了开发期，仍然会有新想法要验证、
新技术要评估、下一代方案要定——那些都在这条线上跑，**不打断开发线的任何流程**。

三个人：**需求方**出方向与拍板 · **研究席**探索与收敛 · **监督席**核实、给建议、做迁移。

🔴 **研究席有座位，但没有一种权**。它的产出在被核实之前，效力等同「我觉得」——
落在既有的效力顺序里：需求方拍板 > 审查席验证过的事实 > 监督席的意见 > 任何人的「我觉得」。
**四权结构一个字都不因为它而改。**

## 目录规矩

```
ai/RandD/
├── README.md                这一份
├── index.md                 所有话题一览（编号 · 话题 · 开始 · 状态 · 去向）
├── memory.md                🔴 研究席自己的记忆（线级，跨话题；格式同 `ai/memory.md`，≤80 行）
└── NN-topic/                一个话题一个目录，编号只增不减，毕业后原地留档
    ├── README.md            话题卡：要解决什么 · 判据 · 状态（≤50 行）
    ├── 00-status.md         🔴 活的：当前结论 + 下一步（≤200 行，每轮必读）
    ├── 01-open-questions.md 🔴 活的：还没定的（≤100 行）
    ├── 02-ideas.md          🔶 半活：需求方的想法原话，**当轮追加**，收敛时必读
    ├── decisions.md         RD-#### 候选决策台账（毕业时转正式 AD）
    ├── tasks/               R-#### 研究任务，一任务一文件 + index.md
    ├── notes/               N-#### 研究记录：**发现**（世界是什么样）
    ├── drafts/              草案：**主张**（我们该怎么做），还没拍板
    ├── log/                 🔴 死的：完整对话记录（双方逐字），按日期
    ├── lab/                 🔴 死的：实验代码，**三档**（探针 / 原型 / 参考实现）
    ├── runs/                🔴 死的：跑过的数据与结果（大件不入库，用清单记怎么取）
    └── graduation/          毕业申请 · 判据自查 · 迁移清单
```

🔴 **文件名用中性名，内容按项目语言写**——两份模板路径必须一字不差（`ai/template/` 与 `ai/template-en/`），
所以名字不跟着语言走；守门按 **`00-` `01-` `02-` 前缀**认这三份，**改语言不会让守门失灵**。

🔴 **死的那三个平时不读**，只读各自的 `INDEX.md`；只有收敛与复盘时才展开。
**靠结构控上下文成本，不靠自觉，也不靠删内容**——删了毕业就重建不出来。

🔴 **`ai/RandD/` ＝ 未拍板的一切**。拍板后由**监督席**迁出（方案进 `ai/specs/`、候选决策转正式 `AD####`、
产品定义进 `product/`），**这里不留第二份**——一件东西只有一个家，否则两处永远对不上。

### 🔴 三份记录，分工不许混

| 文件 | 记什么 | 谁记 · 何时 |
|---|---|---|
| `log/` | **完整对话流水**：需求方说的 + 研究席回的，逐字、按时间 | 研究席，**当轮追加** |
| `02-想法册.md` | **只摘需求方的想法原话**，按主题聚，带处置与状态 | 研究席，**当轮追加** |
| `00-现状.md` | **当前结论**：已定的、下一步 | 研究席，每轮更新 |

一句话：**`log/` 是发生了什么 · 想法册是他要什么 · 现状是我们定了什么。**

### 🔴 为什么没有 `src/`

① 仓库根已经有一个 `src/`，再来一个，`grep`、IDE、守门脚本全会混淆；
② **叫 `src/` 会产生心理暗示**——「这是源码，能跑就搬过去」，而那正是这条线要挡的事故；
③ 研究阶段的代码本来就有不同的质量标准（没有测试、硬编码路径、不处理错误），**它不该被当成源码**。

代码放 `lab/<编号>-<名>/`，README 第一行标档位：**探针 / 原型 / 参考实现**，
🔴 **没有「可以直接用」这一档**。正确路径：毕业 → 方案进 `ai/specs/` → 开任务 → 开发席重写 → 审查席审。

## 编号

`R-####` 研究任务 · `RD-####` 候选决策 · `N-####` 研究记录。
🔴 **不混进开发线的 `T-####` / `B-####` / `AD####`**：那边有状态机与守门，研究任务过不了（没有验收标准、
经常半途改方向）；把候选决策放进 `ai/decisions/` 等于让**未核实的东西取得效力**。

## 🔴 毕业判据（九条，全绿才能交）

| # | 判据 | 怎么算过 |
|---|---|---|
| 1 | 一句话说清**做什么 · 给谁用 · 不做什么** | 三句都写得出来，「不做什么」不是空的 |
| 2 | **产品名定了**（或明确沿用宿主项目名） | 名字查过：包注册表 + 系统命令 + 同领域公司 |
| 3 | 🔴 **不可逆决策列全了** | 每条写明「改了要全盘返工什么」 |
| 4 | 🔴 **每项技术选型有归属** | 只能三选一：①验证过（给实验编号）②有成熟先例（给出处）③**明说是赌注**＋赌错的退路。**不许有第四种「应该没问题」** |
| 5 | **风险清单** | 每条有**触发信号**与**应对** |
| 6 | **里程碑到 M0** | 第一个可验收的交付物是什么、怎么验 |
| 7 | **遗留待定项各有归属** | 谁定 · 什么时候之前 · 不定会卡住什么 |
| 8 | **实验可复现 + 每份标档位** | `lab/` 里按 README 能跑出同样结果 |
| 9 | **监督席核实过 + 需求方拍板** | 效力顺序的最后一环 |

🔴 **不过就退回探索，不许「先毕业，缺的以后补」**——R&D 欠的账会在开发中期以
「这个当初没验过」的形式爆出来，那时改的代价是十倍。

## 🔴 北极星：毕业时能把整个过程重建出来

所有编号、索引、**三轴互引**（时间 `log/INDEX.md` · 问题 `tasks/index.md` · 主张 `decisions.md`）、
当轮追加，都是为了这一条。**判据：从任一点出发，三跳之内能到另外两轴**；
**换一个全新的会话，只靠这些文件，能不能把毕业产出写出来。**

守门：`bash ops/verify/check-randd.sh`（结构齐全 · 索引有对应行 · 活文件没超行数 · 毕业自查全绿才许标「已毕业」）。
