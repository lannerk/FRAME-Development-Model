# 工程约定

> **动手之前扫一眼标题，避开已经踩过的坑。** 每条后面括号里写它是哪次事故来的。
> 上限 150 行。新增一条就想想能不能合并掉一条。
>
> **§一 §二 §五 §六 §七 是通用的，可以直接用；§三 §四 要按你的项目填。**

---

## 一、版本与回滚

1. **旧版本去版本控制取，不要在仓库里堆副本。**
   ```
   git log --oneline -- <文件>      # 它改过哪些次
   git show <sha>:<路径>            # 把那一版打印出来
   ```
2. **`tmp/` 只保「本段改了、但还没提交过」那一小段窗口**，下段开工即清空。
   不要按段堆旧件——堆到最后没人敢删，只能人工清 GB 级垃圾。
3. **每段收尾写一行 commit message** 放进 `ai/state/now.md` 末尾（这段动了什么 + 对应哪几条决策）。
   提交信息全是 `no message` 的仓库，历史只能按时间找、不能按内容找，等于白存。

## 二、决策与记录

4. **决策编号只有一个分配点**：`ai/decisions/index.md` 顶部「下一个可用编号」，**谁用谁加一**。
   撞号了：**后写的那条改号**，原位留一行「原 ADxxx，因撞号改为 ADyyy」；已被多处引用的那条不动。
5. **任务号同理**：`ai/tasks/index.md` 顶部「下一个可用任务号」。
6. **需求方说的每一句都先进收件簿**（`product/requirements/inbox.md`），当轮记，**一轮结束前处置清零**。
7. **业务取舍列选择题请需求方拍板**，不要开放式提问。小事按推荐先做并登记决策，标 `代拍`。
8. **口头共识当轮落文档**：对话里说的话，当轮写进收件簿或原话目录，不要只记在脑子里。
9. **每段收尾必须改决策的「实现」列**：已交付写「已落地 + 实测（第 N 段）」；只做一半的写清哪一半、另一半在哪条任务。
   多子项的总纲行不要拿一格当进度。**不改的后果是没人能看出还剩什么。**
10. **变更传导整条链**：代码 → 注释 → 对外文档 → 需求/功能清单 → 决策 → `state/now.md`。少一环，下一段就有人按旧文档开工。

## 三、实现纪律（**条目写在 `ai/rules/conventions-project.md` §三**）

> 这一节是项目专属的：写你们**真的约定过**的东西，别抄通用软工教条——没有事故背书的条目，三个月后没人会看。
> 🔴 **条目本身不写在这里**（需求方 2026-09-27 拍板「拆出去」）：它们是项目自有内容，写进 `ai/rules/conventions-project.md`，
> 那一份在 `classes.txt` 里是 **seed**（同步永不覆盖、也永不推回源仓库）。以前它们长在这份 `follow` 文件里，
> 于是**每次分发都把它报成「目标改过」、要人合一次**，而 `push=yes` 的项目反过来会**把自己的命令推进 FRAME**。
> **编号连续**，别处的引用（「§四.22」「自检 #20」这种）照旧成立。

## 四、前端 / 界面（**条目写在 `ai/rules/conventions-project.md` §四**；没有界面就整节留空）

> 🔴 **模块顶层不许声明和宿主环境的全局同名的东西**（2026-09-28，实测一次）：某个前端模块顶层写了 `const CSS = …`，
> **把浏览器的 `CSS` 遮住了**，同一份文件里后面的 `CSS.escape(...)` 于是**点到那一下才抛**——报错在别的函数里、别的模块照样好用、刷新也还在。
> 语法完全合法，静态检查查不出来。判据交给机器按**名字**判（顶层声明 vs 那张宿主全局名单），
> **名单和扫哪个目录是项目自己的事**，所以那条守门起名 `ops/verify/check-project-*.sh`。

> 通用的那一条留在这里：**「改了 X 记得同时改 Y」这类规矩靠人记就等于没有。**
> 本模板的来源项目为它连踩两次——前端文件推上去了、sha 也对、日志也正常，浏览器就是用旧的，因为版本串忘了改。
> 做法：**把它变成算出来的**（版本串 ＝ 那个文件内容的指纹），再配一条守门重算并对账，支持 `--fix`；
> 项目专属的那几格（扫哪个目录、什么前缀）**必须是旋钮**（`ops/verify/paths.env`），写死了换个项目就是假红。
> 🔴 **算指纹之前先去掉回车**，否则同一份内容在 Windows 签出的机器上指纹不同，守门会无缘无故变红。

## 五、交付前自检（**清单写在 `ai/rules/conventions-project.md` §五**，缺一不算完）

> **这是最重要的一节**：它定义了「做完了」是什么意思。
> 每一条都应该能**一条命令跑出来**，人不用判断。原始输出贴 `claude-outputs/developer/`。
> 🔴 **本项目特有的检查不要在这里加一行、也不要去改 `ops/verify/check-all.sh`**——
> 起名 `ops/verify/check-project-*.sh` 就会被自动跑（那类文件永不进模板、也不被模板覆盖）。

**清单之外还有「自测」**（`ai/roles/developer.md` §五之二）：**你做的功能，你自己先当一次用户走一遍**——
按任务「验收」逐条走；UI **对着定稿原型一比一比**（颜色用令牌、图标直接取用、空／加载／错误／禁用四态 + 窄屏 + 深色），截图贴回报；
碰过的公共依赖顺手点一下别的调用方；修过的 bug 重跑原复现步骤。
**机器自检证明不了「这功能能用」**，那部分只能人走。自测不替代审查——**你测不出自己的盲区**。

**清单之外还有两条，同样不能省**：

- **真机 / 真实环境验证**，不是「应该能跑」。**单元测试只测纯函数等于没测**——要测就测到它真正被调用的那一层。
- **新加的守门脚本或守门测试，必须当场故意造错跑一次，把「它确实红了」的输出贴进回报。**
  做不到反向断言的守门，给的是虚假的安全感，比没有更危险。

**反过来也有一条：守门要反向断言（造错看它红），正向测试要前置断言（先证明自己真的在测）。**
这是同一条道理的两面——**绿色必须有意义**。
**「我没复现出来」只有在前置断言全绿时才是结论**，否则它只是「我的台子没跑起来」。
- **守门要判「要保的那件事」本身，不要判它的文本影子。**
  同一件事的文本形状有无数种写法，你堵得完的只是你想得到的那几种。
  **能执行就执行一遍看结果**（沙箱加载、起个进程、发一个真请求），不能执行再退回文本匹配，
  并写明「它拦不住哪几种形态」。
  **真事**：要保证「模块加载时注入样式」，先后想过三种文本判据——数花括号、加标记注释、按位置判，
  三种分别被模板字符串里的花括号、人忘写标记、文件结构打穿；
  换成把模块丢进沙箱真加载一遍看结果，连三种文本判据全都漏掉的那种形态都拦得住。

## 六、常跑的守门（模板自带，开箱可用）

🔴 **每条守门都要报「扫了多少份」，扫到空集就报红**（2026-09-28，需求方拍板的第 2 层）。
判据一句话：**一条扫不到东西的守门永远是绿的，而那是最危险的绿**——它给的是「已经查过」的错觉。
所以每条 `check-*.sh` 的绿输出里都要有数（「扫了 N 份」「N 个来源」「N 处引用」这种），
**N=0 时报红或 SKIP，不许报 OK**：真不适用就说 SKIP（说明为什么），别拿空扫当通过。
配套是**名单法**：名单只许缩小（修好一条删一条），要扩大得说明为什么；
一次都扫不到就判「扫描器坏了」，**先修扫描器，不许先信那个绿**。


| 脚本 | 查什么 |
|---|---|
| `ai/check-links.sh` | 文档里指不到东西的路径。**断链必须为 0** |
| `ops/verify/check-paths.sh` | 脚本/文档里写死的机器 IP 与已废弃的旧目录名；**双引号 `echo` 里的反引号**（那是命令替换，`bash -n` 查不出来） |
| `ops/verify/check-inbox.sh` | 收件簿里还有没有没处置的需求方发言。**一轮结束前必须清零** |
| `ops/verify/check-bugs.sh` | bug 闭环断没断：复现步骤是不是真写了、修完有没有复测、关闭有没有依据。**一轮结束前必须绿** |
| `ops/verify/check-ledger.sh` | 任务字段齐不齐、**状态双写一致不一致**、**同一个编号有没有第二份文件**、索引与实体对不对得上、`ai/` 根下有没有散件 |
| `ops/verify/check-writeback.sh` | `tmp/writeback-pending/` 里还挂着没写回仓库的改动没有 |
| `ops/verify/check-mail.sh` | **席间信箱**没烂掉：只放未读 · 字段齐 · 没有陈信（>7 天）· 没有重复信 · 每份投递口没超过 20 封 · 没有没登记的外部投递口 · 没拿信箱派活 · 归档一席一月一份 |

## 七、该删就删、该更新就更新

**仓库会烂，是因为没人敢删。** 那些「先留着吧」的东西，一年后就是没人敢碰的垃圾山。

| 遇到 | 就 |
|---|---|
| `tmp/` 里本段的临时件 | **本段收尾删掉**，别留给下一段 |
| 同一份东西有第二个副本 | 留一份，**另一份删**，并在决策里记留的是哪份、为什么 |
| 指向已不存在目录/文件的规则、引用、脚本行 | **直接删**，不要注释掉留着 |
| 已经作废的方案、被取代的决策 | **移进 `archive/`**（这类是「归档不删」——它们是历史依据） |
| 过时但还成立的文档段落 | **更新它**，不要在旁边再写一段新的 |

**判据**：删之前问一句「它的信息在别处还有吗」——有（版本控制、活文件、archive）就删；没有就先让它有，再删。
**删不是破坏，留一堆没人维护的东西才是。**

## 八、文件与目录

23. **挪文件/改目录，当轮重扫所有引用它的路径**，并跑 `ai/check-links.sh`（断链必须为 0）。
24. **同名脚本不许有第二份。** 部署运维脚本只放 `ops/scripts/`，跟着源码走的自检脚本放 `src/<project>/tools/`。
25. **`tmp/` 里的东西任何正式文件都不许引用。**
26. **机器信息只在 `ops/machines.json`，仓库内路径只在 `ops/paths.ps1`**，别处不许写死。
