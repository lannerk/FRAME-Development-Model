# 工程约定

> **动手之前扫一眼标题，避开已经踩过的坑。** 每条后面括号里写它是哪次事故来的。
> 上限 150 行。新增一条就想想能不能合并掉一条。
>
> **§一 §二 §五 §六 §七 是通用的，可以直接用；§三 §四 要按你的项目填。**

---

## 一、版本与回滚

1. **旧版本去版本控制取，不要在仓库里堆副本。**
   ```
   git log --oneline -- <文件>      # 它改过哪些次
   git show <sha>:<路径>            # 把那一版打印出来
   ```
2. **`tmp/` 只保「本段改了、但还没提交过」那一小段窗口**，下段开工即清空。
   不要按段堆旧件——堆到最后没人敢删，只能人工清 GB 级垃圾。
3. **每段收尾写一行 commit message** 放进 `ai/state/now.md` 末尾（这段动了什么 + 对应哪几条决策）。
   提交信息全是 `no message` 的仓库，历史只能按时间找、不能按内容找，等于白存。

## 二、决策与记录

4. **决策编号只有一个分配点**：`ai/decisions/index.md` 顶部「下一个可用编号」，**谁用谁加一**。
   撞号了：**后写的那条改号**，原位留一行「原 ADxxx，因撞号改为 ADyyy」；已被多处引用的那条不动。
5. **任务号同理**：`ai/tasks/index.md` 顶部「下一个可用任务号」。
6. **需求方说的每一句都先进收件簿**（`product/requirements/inbox.md`），当轮记，**一轮结束前处置清零**。
7. **业务取舍列选择题请需求方拍板**，不要开放式提问。小事按推荐先做并登记决策，标 `代拍`。
8. **口头共识当轮落文档**：对话里说的话，当轮写进收件簿或原话目录，不要只记在脑子里。
9. **每段收尾必须改决策的「实现」列**：已交付写「已落地 + 实测（第 N 段）」；只做一半的写清哪一半、另一半在哪条任务。
   多子项的总纲行不要拿一格当进度。**不改的后果是没人能看出还剩什么。**
10. **变更传导整条链**：代码 → 注释 → 对外文档 → 需求/功能清单 → 决策 → `state/now.md`。少一环，下一段就有人按旧文档开工。

## 四、前端 / 界面（**按你的项目填，没有界面就整节删**）

16. `<样式令牌的唯一出处是哪个文件；新代码不许写死颜色和数字>`
17. `<同类控件全系统一个样式；新控件先找现成的复用>`
18. **缓存/版本号这类「改了没效果」的坑：把它变成算出来的，再配一条守门。**
    一句「改了 X 记得同时改 Y」的规矩**靠人记就等于没有**——本模板的来源项目连踩两次：
    前端文件推上去了、sha 也对、日志也正常，浏览器就是用旧的，因为版本串忘了改。
    做法：版本串 ＝ 那个文件内容的指纹（sha256 前几位），配一条守门重算并对账，支持 `--fix`
    （`ops/verify/check-cachebust.sh` 就是这个形状：三个旋钮 `CACHEBUST_WEB` / `_PAGE` / `_PREFIX`，**不适用就自己跳过**——
    项目专属的那几格必须是旋钮，写死了换个项目就是假红）。
    🔴 **算指纹之前先去掉回车**，否则同一份内容在 Windows 签出的机器上指纹不同，守门会无缘无故变红。

## 五、交付前自检（**按你的项目填**，缺一不算完）

> **这是最重要的一节**：它定义了「做完了」是什么意思。
> 每一条都应该能**一条命令跑出来**，人不用判断。原始输出贴 `claude-outputs/developer/`。

| # | 跑什么 | 它是哪次事故留下的 |
|---|---|---|
| 19 | `<构建>` | `<仓库里躺过编不过的文件？>` |
| 20 | `<静态检查>` | |
| 21 | `<测试>` | |
| 22 | `<本项目特有的检查，例如语法扫描 / 路径对账 / 规范 lint>` | |

**清单之外还有「自测」**（`ai/roles/developer.md` §五之二）：**你做的功能，你自己先当一次用户走一遍**——
按任务「验收」逐条走；UI **对着定稿原型一比一比**（颜色用令牌、图标直接取用、空／加载／错误／禁用四态 + 窄屏 + 深色），截图贴回报；
碰过的公共依赖顺手点一下别的调用方；修过的 bug 重跑原复现步骤。
**机器自检证明不了「这功能能用」**，那部分只能人走。自测不替代审查——**你测不出自己的盲区**。

**清单之外还有两条，同样不能省**：

- **真机 / 真实环境验证**，不是「应该能跑」。**单元测试只测纯函数等于没测**——要测就测到它真正被调用的那一层。
- **新加的守门脚本或守门测试，必须当场故意造错跑一次，把「它确实红了」的输出贴进回报。**
  做不到反向断言的守门，给的是虚假的安全感，比没有更危险。

**反过来也有一条：守门要反向断言（造错看它红），正向测试要前置断言（先证明自己真的在测）。**
这是同一条道理的两面——**绿色必须有意义**。
**「我没复现出来」只有在前置断言全绿时才是结论**，否则它只是「我的台子没跑起来」。
- **守门要判「要保的那件事」本身，不要判它的文本影子。**
  同一件事的文本形状有无数种写法，你堵得完的只是你想得到的那几种。
  **能执行就执行一遍看结果**（沙箱加载、起个进程、发一个真请求），不能执行再退回文本匹配，
  并写明「它拦不住哪几种形态」。
  **真事**：要保证「模块加载时注入样式」，先后想过三种文本判据——数花括号、加标记注释、按位置判，
  三种分别被模板字符串里的花括号、人忘写标记、文件结构打穿；
  换成把模块丢进沙箱真加载一遍看结果，连三种文本判据全都漏掉的那种形态都拦得住。

## 七、该删就删、该更新就更新

**仓库会烂，是因为没人敢删。** 那些「先留着吧」的东西，一年后就是没人敢碰的垃圾山。

| 遇到 | 就 |
|---|---|
| `tmp/` 里本段的临时件 | **本段收尾删掉**，别留给下一段 |
| 同一份东西有第二个副本 | 留一份，**另一份删**，并在决策里记留的是哪份、为什么 |
| 指向已不存在目录/文件的规则、引用、脚本行 | **直接删**，不要注释掉留着 |
| 已经作废的方案、被取代的决策 | **移进 `archive/`**（这类是「归档不删」——它们是历史依据） |
| 过时但还成立的文档段落 | **更新它**，不要在旁边再写一段新的 |

**判据**：删之前问一句「它的信息在别处还有吗」——有（版本控制、活文件、archive）就删；没有就先让它有，再删。
**删不是破坏，留一堆没人维护的东西才是。**
