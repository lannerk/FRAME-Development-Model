# 《FRAME 角色与任务的模型及 Effort 指定规则》（简称「指定规则」）

> **默认关。** 开关在 `ai/frame-repo.conf` 的 `tier-rule=`，没写就是 `off`。
> **关着 = 和没有这份规则时一样**：各席照所用工具自己的默认派子代理，任务里写的标签只是信息。**开着** = 派子代理照标签选档。
> 🔴 **「一个会话同时派几个子代理怎么分活」不归这份管**——那五条常开，在 `ai/rules/workflow.md` §七之三。
> 这份规则由需求方 2026-10-10 拍板（他的原话：派任务、写角色与子代理时「不要具体写模型，而是类似写代码用接口的方式，不同的 ide 只是根据它们的文件说明去实现」）。

## 一、管什么、不管什么

| | 管 | 不管 |
|---|---|---|
| 会话 | **子代理**：派活时用哪一档 | **主会话**：模型和等级是人开会话时选的，FRAME 指定不了 |
| 文件 | 本规则；四档子代理文件；`ai/ide/` 各工具一份实现文件；`ai/frame-repo.conf` 里的开关与工具两行 | 各工具的用户级目录（每个人自己的） |

## 二、接口：四档

| 档 | key / 子代理文件名 | 一句话 | 谁能到这一档 |
|---|---|---|---|
| 顶 | `top` / `tier-top` | 这种工具里最强最贵的组合，宁贵勿错 | **只有两条路**：升档申请被需求方批准，或人直接指定；记录写 `top (approved <日期>)`。**标签里不许直接写 `top`** |
| 强 | `strong` / `tier-strong` | 判断对错、要多想几层、错了代价大 | 标签 `strong` |
| 中 | `normal` / `tier-normal` | 规则清楚、照着做 | 标签 `normal`（**缺省**，不写就是它） |
| 轻 | `light` / `tier-light` | 对错一眼能查 | 标签 `light` |

1. **文件里只写 key**：`strong` `normal` `light` `top` `complex`，中英项目一样（换语言不用改）。**规矩、手册、任务里不写模型名和等级名**——它们只出现在 `ai/ide/<工具>.md`。
2. 每种工具四个子代理文件，名字固定 `tier-top` `tier-strong` `tier-normal` `tier-light`；主会话派活时按名字叫：「用 `tier-strong` 做这一段」。
3. 四个文件**不放项目知识**：正文只有「你是执行子代理，照主会话给的活做」；活的内容在派活的话里。所以它们随 FRAME 走，不随项目改。
4. 做不到四档的工具，在它的实现文件里写明怎么合并（例如「顶＝强」）；接口和标签不变。
5. 🔴 **能上调不能下调**：做的人觉得比标的难，用**弹窗选择题**向需求方申请升一档（写清为什么、大约多花多少），点头才换，并在任务或记录里写一句。往下调不许。

## 三、标签：难度三档 ＋ 复杂度

| 标签 | 档 | 什么活 |
|---|---|---|
| `strong` | 强 | 判断对错、要多想几层、错了代价大：公共层的核、安全检查、键盘与读屏、状态机、改规矩的措辞、技术方案、核稿下结论、定位不知道原因的 bug |
| `normal` | 中 | 规则多但每一条都明白：照规格做一个件、逐条核、写用例、修已定位的 bug、写文档与调研 |
| `light` | 轻 | 对错一眼能查：跑检查与脚本、复测、数数、对名字、批量改名、整理记录与归档 |

- 🔴 **三类永远按 `strong`，不看谁标**：① 安全（外来数据当地址、HTML、CSS、正则用的地方）；② 无障碍（键盘、焦点、读屏）；③ 改已经转正的东西（规格、规矩、已实现的）。
- **`complex`**（复杂度，和难度分开判）：要读的超过一个子代理一次装得下、要动的文件超过十来个、分段的人之间要对名字或接口、做完要和别人合——**满足任一条就加**；加了就照 `ai/rules/workflow.md` §七之三 拆。**难度决定用哪一档，复杂度决定拆不拆**——一次塞给一个子代理的漏，换再强的档也救不回来。

**按场景的缺省**（标的时候参考，可以按具体情况改）：设计、技术方案、写公共层与生成器、定位原因不明的 bug、核稿下结论 → `strong`；照规格做一件、写用例、修已定位的 bug、写文档、逐条核 → `normal`；简单展示件、跑检查与脚本、复测、翻译与批量改名、记录与归档 → `light`。一族、一批、公共层几乎总是 `complex`。

## 四、谁标、写在哪

| 席 | 怎么定 | 写在哪 |
|---|---|---|
| **开发** | **审查席**开任务 / bug 时把活分成几段、每段标；开发主会话照标签派；没标的按 `normal` | 任务 / bug 文件的 `subagents:` 段 |
| **审查**（审别人的活） | 固定：核稿下结论、审大件代码 → `strong`；逐条核一族、抽查、写用例 → `normal`；跑检查、脚本、对名字 → `light` | 不用写 |
| **审查**（自己派给自己的活） | **自己标**（写规格、做裁定、写样板都算），和给开发席标一样 | 它自己的任务 / 进度文件 |
| **监督** | 固定：核大件、重跑关键实测 → `strong`；分组核稿 → `normal`；跑脚本、统计 → `light` | 不用写 |
| **维护** | 固定：改规矩、写规范 → `normal`（措辞由主会话把关）；跑守门、整理记录、查引用 → `light` | 不用写 |
| **研究** | 自己标，每一步照第三节 | 研究记录 |

格式（任务、bug、研究记录、审查席自己的任务都一样）：

```
subagents:
- <这一段做什么，用项目自己的语言写>: strong
- <一族展示件>: normal, complex
- <批准升档的那一段>: top (approved 2026-10-10)
```

段名 `subagents:`、key、逗号是固定的；冒号前那句话用项目的语言写。守门只认这几个 key。

## 五、开关与工具：两行，在 `ai/frame-repo.conf`

```
ide=claude-code        # 工具名＝ai/ide/ 里那份实现文件的名字；没定写 undecided；某一席单独用别的工具加一行 ide.<席>=<工具>
tier-rule=off          # on / off，没写就是 off
```

放在维护席自己的这份文件里（每个仓库一份、同步不覆盖），**不放 `ai/state/now.md`**：那份归审查席、是全仓改得最勤的文件，每次开关都去代改它，会把别席没提交的改动一起带走。`now.md` 顶部 🔔 行在开关变化时写一句当前状态，各席开场照样看得到。

| 对维护席说 | 做什么 |
|---|---|
| `模型档位指定 开` | `tier-rule=on`；当前工具的四档子代理文件没生成的先生成；**那份实现文件 `verified: no` 的先实测**（第六节）；🔔 行写一句；维护记录一条 |
| `模型档位指定 关` | `tier-rule=off`；子代理文件留着不删；🔔 行写一句 |
| `模型档位指定 状态` | 回一句：开关、工具、四档文件在不在、实现文件多久没核、实测过没有 |
| `ide <工具> [席]` | 改 `ide=`（给某一席单独换就写 `ide.<席>=`）；按 `ai/ide/<工具>.md` 生成那种工具的四档文件；旧工具的文件不删（各工具只读自己的目录，互不干扰）；维护记录一条 |

**开关状态以派活那一刻为准，不追溯**：关着时标的、后来开了 → 照标签派；开着时标的、后来关了 → 标签留着、不强制；已经派出去的子代理不动；批准过的升档记录留着，再开时仍按批准的档。为什么不追溯：追溯要有人去翻每份任务判「这段是开着时标的还是关着时标的」，谁也不会去做；按那一刻判，各席一眼能定。

## 六、各工具一份实现文件：`ai/ide/<工具>.md`

写清这种工具里四档各对什么模型与等级、子代理文件放哪、怎么写、做不到什么、怎么更新；格式与更新办法在 `ai/ide/README.md`。

- **只写一份英文**，中英项目共用——内容是路径、字段、模型 ID 和官方文档链接，官方文档本来就是英文，写两套只会各自走样。
- 头部 `verified: no` 的是照官方文档写的、还没在项目里实测过。🔴 **开开关之前，当前工具那一份要先实测**：在项目里真派一次 `tier-light`、一次 `tier-strong`，看实际跑的模型和等级对不对，对了改成 `verified: yes` 并写上日期。
- 维护席每次「同步 FRAME」顺手跑 `bash ops/scripts/ide-refresh.sh --all`，看各工具的版本变没变、多久没核。

## 七、守门 `ops/verify/check-ide.sh`

- 一直查：`tier-rule=` 只许 `on` / `off`；`ide=` 写了工具就得有那份实现文件；规矩、手册、`CLAUDE.md` 里不许出现模型名（等级名是普通英文词，不在正文里查）。
- 只在 `tier-rule=on` 时查：当前工具的实现文件 `verified: yes`；四档子代理文件齐；任务、bug、研究记录里 `subagents:` 段的值只许是第四节那几个 key。
- 只提醒不报红：实现文件 `checked:` 超过 90 天。
