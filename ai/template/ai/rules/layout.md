# 目录规范 · 东西该放哪

> **总原则：按「这东西有没有生命周期」分，不按「谁写的」分。**
> 有状态、会被反复引用、多角色共写的（任务/决策/方案/需求）→ 各自的固定目录；
> 一次性的、属于某个角色的（报告、截图、实测、研究）→ `claude-outputs/<角色>/`；
> 三方都要看的素材 → `claude-outputs/shared/`。
>
> **一件东西只有一个家。** 现在这份结构里，没有任何一类东西可以放在两个地方。

## 一、顶层

|---|---|---|---|

### `docs/` 谁来改：被它挡住的人当场改

`docs/` 是工程文档（架构、目录说明、运维、真机链路），**四席都可能读它、也都可能被它挡住**。

**规矩**：**谁照着文档做、发现文档是错的，谁当场改**，并在 `ai/state/now.md` 的「别再踩的」记一条。
**不要开任务等别人改**——下一个人会踩同一个坑，而开任务的成本比改一行大得多。

改的时候两件事：①**真跑一遍**确认新写法对（**文档里的命令也是代码**）；②在回报或维护记录里说一句改了什么。
**这条不适用于 `ai/rules/` 与 `ai/roles/`**——那两处归维护席，发现问题告诉需求方转维护席。

### 入库与不入库：只有两个目录不入库

**`tmp/` 和 `dist/`，就这两个。其余一切都入库。**

- 要造一次性的文件或目录 → 造在 `tmp/`；构建产物 → `dist/`。
  **不要在别处造完再回来加 `.gitignore` 规则**——那正是以前长出六个 `_to_delete/`（17MB / 109 文件）的过程。
- **别把「一次性」和「随手产出」搞混**：监督者的方案、审查记录、真机截图、实测数据**看着像一次性产出，其实要入库**，
  它们是以后复核的依据；而打包发布过程中生成的东西**看着很重要，其实用完就没用**，随时能重新构建。
- 旧文件副本**哪都不放**——git 里全有（`conventions.md` §一）。
  **唯一的例外是初始化迁移的那一次快照** `archive/legacy-<日期>/`——旧项目可能根本没进过 git，
  git 里找不回来，所以那一份要留（`docs/guide/project-init.md` §3.4）。例外只此一次。

**为什么要有预算**：旧结构四个「活文件」加起来 1.78MB，任何会话读上两个就是几十万 token。
🔴 **放宽任何一条上限 ＝ 改规范。** 要在 `ai/rules/maintenance-log.md` 记一条，
写清**上调前后是多少、为什么、挪走了什么**。**「职责多了所以把尺子放大」不是理由**——
那等于预算不存在。守门：`bash ops/verify/check-budget.sh`（它从这张表读数，不自己抄一份）。

**真正要管的那笔成本是「开场必读总量」**，硬顶写在 `ops/verify/check-budget.sh` 里，
由它按**实际行数**算，不采信任何文档里写的数字——**这三处以前各写了一个不同的数**。

> **往开场必读里加东西，必须先说清楚挤掉了什么**；通用方法放 `ai/rules/`，四席各留一句指路。

**预算不是洁癖，是成本。** 开场必读多少行，跑 `bash ops/verify/check-budget.sh` 看当前实测值。

### 🔴 规矩只有维护席能改 —— 别人发现了就**提示需求方转告**

**四席里只有维护席能动这几样**：`ai/rules/*`、`ai/roles/*`、`CLAUDE.md`、目录规范、守门脚本、两份模板。

| 你是 | 你发现「这儿该加一条规矩 / 这条铁律不对 / 守门漏了一种情况」 |
|---|---|
| 开发席 · 审查席 · 监督席 | **不许自己改，改法是发信**：`ai/mail/to-maintainer/from-<你这一席的英文名>.md`（developer / reviewer / supervisor）（现象＋证据＋拟改法＋代价；正文超三行写成 `claude-outputs/<你这一席>/<日期>-<题>.md`，信里只留路径）。**不用需求方当传输层**；**只写在任务/报告里不算转告**（`ai/rules/requester.md`）。**判据：这条建议是不是「这条任务要解决的事」？不是就发信** |
| 维护席 | 需求方确认之后才动，记进 `ai/rules/maintenance-log.md`，**中英两份模板当轮同步** |

**唯一的例外是 `docs/`**：谁照着文档做、发现文档是错的，**谁当场改**（本文件 §一那条）。
`docs/` 是工程文档，不是规矩。

> **为什么要卡这么死**：规矩是四席共同的坐标系。**任何一席能单方面挪坐标系，其余三席就会在不知情的情况下走偏**——
> 而这种偏差没有任何症状，直到两轮之后有人按新坐标做完一件事、另一人按旧坐标审它。

### `CLAUDE.md` 的成本是**乘以会话数**的

`CLAUDE.md` **每个会话都会加载一次**，所以往里加一行，代价是「一行 × 你开过的所有会话」。

**判据只有一句**：**不知道它就会走错路的，才进 `CLAUDE.md`**；其余一律进 `ai/rules/` 或角色手册，
`CLAUDE.md` 里只留一句指路。

| 该进 | 不该进 |
|---|---|
| 身份口令表（不知道就不知道自己是谁） | 某条规矩的完整细则 |
| 常用口令（不知道就用不起来） | 举例、来由、事故复盘 |
| 铁律的一句话版 | 目录明细（那是 `ai/index.md` 的活） |
| 「有事只跟审查席说」这类走向 | 任何一席专属的流程 |

**守门**：`bash ops/verify/check-budget.sh` 盯着它的行数上限；**放宽上限＝改规范，要进维护记录**。

### 命名用哪种语言：**目录一律英文，内容产物跟需求方的语言**

| 什么 | 用哪种语言 | 为什么 |
|---|---|---|
| **所有目录名** | **一律英文** | 结构要跨语言通用；守门、索引、跨项目复用全靠它们对得上。**除非需求方明确要求，或他自己建的目录** |
| **结构性文件**（`CLAUDE.md` `README.md` 各 `index.md` 规则与角色手册、脚本、配置）与**编号**（`T-####` `AD####` `B-####` `M-##`） | **一律英文 / 数字** | 它们是骨架和检索键，不是产物 |
| **内容产物**——技术方案、数据库设计、说明文档、需求规格、报告：**文件名和内容** | **用需求方选的沟通语言** | **文件名是给人找东西用的。** 他要在文件管理器里一眼认出「哪份是 VPN 的方案」，英文缩写做不到 |

🔴 **占位目录不许用尖括号**，用 `_PROJECT_` 这种。`<>:"|?*` 在 **Windows 上是非法文件名字符**，
而 AI 多半跑在 Linux 上——**那边建得出来，没有任何症状**，直到需求方在 Windows 上打开图形客户端才炸
（真事：SourceTree 报 `Invalid argument`）。**文档正文里写 `<project>` 是对的**，那是占位说明不是真目录。
守门：`bash ops/verify/check-filenames.sh`。

🔴 **搬文件、转正、归档的时候，原来叫什么就还叫什么。**
**不许顺手「规范化」成英文缩写**——那等于把需求方认得的名字换成只有你认得的代号。
真要改名，**得他点头**。

> **真事**：一次结构迁移里，技术方案目录下 32 份文档被一并改成了英文短名。
> 目录改英文是需求方定的，**文件名不是**——是搬的人自己顺手做的。
> 结果需求方在自己的方案目录里认不出哪份是哪份。**后来靠文件头里记的原路径全部还原了**，
> 这也说明了另一件事：**搬文件时把原路径写进文件头，是能救命的**。

## 四、`claude-outputs/` —— Claude 的草稿区

| 子目录 | 放什么 |
|---|---|
| `developer/` | 自检原始输出、实测数据、交付说明 |
| `reviewer/` | 审查记录、派工单、真机反馈整理、对监督产出的核实记录 |
| `supervisor/` | 监督的报告、方案、研究 —— **原样入库，任何人不改一个字** |
| `shared/prototype/` `shared/screenshot/` `shared/measurement/` | 三方都要看的素材 |

**它是草稿区，不是第二个正式目录。** 东西被采纳之后要**搬到它该在的地方**——
搬去哪一条条列在 `claude-outputs/README.md` 的「转正表」里，采纳时照着搬。
截图、实测输出这类**证据不转正**，永远留在这儿，由任务文件引用。

## 五、方案文件必须有的文件头（「定案后＝开工必读、随时更新」靠它成立）

```
---
状态: 提案 | 已定 | 已作废（被 xxx 取代）    ← 只有三种，别自创
版本: v1.3
最后更新: 2026-09-16
关联决策: AD<编号>, AD<编号>
引用它的任务: T-0001, T-0003
---
## 变更记录
| 日期 | 版本 | 改了什么 | 谁 |
```

四条规矩：

1. **任务的「关联方案」必须指向一份方案或一条 AD**，不许只写「按上次说的」。
2. **谁改实现谁改方案**，同一段里做完。实现和方案不一致而方案没动，等于下段有人照错的开工。
3. **「引用它的任务」是双向的**：任务里写关联方案，方案里写有哪些任务在用它。
4. **方案不记「实现到哪了」**——那是任务和 AD 实现列的事。方案只说「该怎么做」。
   **作废不删**：改文件头、移进 `specs/archive/`、在 `specs/index.md` 的作废表里留一行并指向取代它的那份。

## 六、明确不允许

- 在 `ai/` 根下放散件（只有 `index.md` 和 `check-links.sh`）。
- **改了角色手册或 `rules/` 却不同步 `template/`**——模板一旦落后，下次开新项目就是照着过时的做法起步，而且没有任何症状。守门：`ops/verify/check-template-sync.sh`。
- 同名脚本有第二份（曾经三处各有一个 `push-web.ps1`，内容都不一样）。
- 把自检日志、截图、临时文件放进 `ai/tasks/` 或 `ai/decisions/`。
- 从 `tmp/` 引用任何东西。
- **在任务文件里指向 `claude-outputs/` 的方案或设计稿**——那是草稿区，指过去等于让开发照没定稿的东西做。
  转正路径见 `claude-outputs/README.md` 的两个 § 小节。
- **在文档或脚本里写死测试机 IP**——测试机会增减、IP 会变，唯一出处是 `ops/machines.json`，按 `id` 引用（实测旧仓库里一个 IP 出现了 124 次）。
- **在脚本里写死仓库内路径**——用 `ops/paths.ps1` 的 `$Src` / `$Dist` / `$Tmp` / `$Outputs`。
- 新建第二份「待办」或第二份「交接」。**待办 ＝ `ai/tasks/index.md`，交接 ＝ `ai/state/now.md`**，不再有别的。
- 按段堆旧文件副本——旧版本去 git 取（`conventions.md` §一）。
## 七、文件归属：**谁的文件谁提交，红了归谁**

**这张表是唯一出处**：`ops/scripts/commit-round.sh` 从这里读归属（跟预算表同一个规矩——
**不许在脚本里另抄一份**），`规范巡检` 报红时「这条归谁」也照它判（`CLAUDE.md` §二）。

| 路径（前缀或通配） | 归谁 |
|---|---|
| `CLAUDE.md` · `AGENTS.md` · `README.md` · `FRAME-Development-Model.md` | 维护席 |
| `ai/index.md` · `ai/glossary.md` · `ai/frame-manifest.txt` · `ai/check-links.sh` | 维护席 |
| `ai/rules/*` · `ai/roles/*` · `ai/mail/README.md` | 维护席 |
| `ai/template/*` · `ai/template-en/*` | 维护席 |
| `ops/verify/*` · `ops/scripts/*` · `ops/frame/*` · `ops/README.md` · `docs/guide/*` · `claude-outputs/README.md` · `ai/frame-repo.conf` | 维护席 |
| `ai/tasks/*` · `ai/bugs/*` · `ai/decisions/*` · `ai/specs/*` · `ai/state/*` | 审查席 |
| `product/*` · `claude-outputs/reviewer/*` | 审查席 |
| `src/*` · `dist/*` · `claude-outputs/developer/*` | 开发席 |
| `claude-outputs/supervisor/*` | 监督席 |
| `ai/RandD/*` | 研究席 |
| `ai/mail/to-researcher/*` | **共写**（研究席与监督席、审查席） |
| `ai/memory.md` · `ai/mail/to-*` · `ai/mail/archive/*` · `ops/machines.json` · `docs/ops/*` | **共写**（四席都能写） |

🔴 **这张表判的是「谁维护」，不是「谁许可动」**：需求方拍板的任务单可以派别席动这里的文件，
但做活那一席**当轮必须发信通报归属席**，由归属席复核（`ai/rules/workflow.md` §三之四）。

🔴 **提交只提交自己的**（`ops/scripts/commit-round.sh --seat <席>`）。
**两次实测**：`acf7217` 我用 `git add -A` 把审查席与监督席同时在改的 10 个文件裹进了我的提交信息；
半小时后审查席提交 `992ed79` 时，我暂存好的 6 个文件差一点被它裹走。**这不是偶发，是默认行为。**
所以脚本改成：**发现改动横跨两席以上就停下**，列出「哪几个是谁的」，
让你用 `--seat` 只提交自己的，或明确 `--all-seats` 一起提交。
