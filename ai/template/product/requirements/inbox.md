# 收件簿 —— 需求方说过的每一句，都在这里有一行

> **需求方只跟审查者说话。** 他说的 bug、要做的东西、问题、临时决定，**全部先进这张表**，一句都不许漏。
> **只追加，不删行。** 处理完了改「处置」和「状态」，**不要把行删掉**——删了就没人知道这件事被处理过。
> 表在下面，新的追加在**表尾**。

## 规矩（审查者照做）

1. **收到就记，当轮记。** 需求方一条消息里说了三件事，就记三行。**别等「等我整理好再记」——那一刻就是丢失发生的时候。**
2. **原话逐字摘录**，不要复述。复述会把**目的**丢掉，只剩表面动作，而目的才是判断做法对不对的依据。
   长的（一整段需求、带截图的反馈）另存 `verbatim/<日期>-<话题>.md`，表里填文件名 + 一句话摘要。
3. **每一行都必须有处置**：转成任务 `T-####` / 转成规格 / 当场答复 / 记一条决策 / 不做（**写明为什么**）。
4. **一轮审查结束前，`待处理` 必须清零**——要么有了去处，要么明确写「不做 + 原因」。
   收尾时跑一次 `bash ops/verify/check-inbox.sh`，它会把还没处置的行列出来。
5. **答复需求方时逐条对**：说清每一条的去处（「这三条我开成了 T-0042/43/44，这一条我建议不做，因为……」）。
   **他提的每一件事都要听到回音**，哪怕回音是「不做」。

## 状态

| 状态 | 意思 |
|---|---|
| `待处理` | 刚记下来，还没定去处。**一轮结束前不许还有这个状态** |
| `待确认` | 需要需求方拍板才能定，已经给了选择题，等回话 |
| `已转任务` | 处置列里写任务号 |
| `已转规格` | 处置列里写规格文件名 |
| `已答复` | 是个问题不是活，当场答完了 |
| `不做` | 处置列里**必须写为什么** |

## 表

| # | 日期 | 需求方原话（逐字摘录） | 类型 | 处置 | 状态 |
|---|---|---|---|---|---|
| 1 | \<YYYY-MM-DD> | \<把他说的话原样抄进来，长的填 `verbatim/xxx.md`> | bug / 需求 / 问题 / 决定 | \<T-0001 / specs/xxx.md / 已答复：… / 不做：…> | 待处理 |

> 类型只有四种：**bug**（坏了）/ **需求**（要做的新东西）/ **问题**（他在问，不一定是活）/ **决定**（他拍板了，要记成决策）。
> 分不清就记 `需求`，处置时再改。**分类不重要，不漏才重要。**
