# runner：AI 各席在需求方的 Windows 电脑上跑命令

> **谁读这一份**：任何一席，在会话里跑不了某条命令的时候（铁律 5，`ai/rules/laws.md`）。
> 脚本是 `ops/scripts/seat-runner.ps1`（文件头是实现的依据）；登记表 `ops/scripts/seat-runner.conf`（项目自己的，`seed`）。
> 来历：一个消费项目三支 runner 各开一个窗口、各管一席，需求方定了「做成统一一个 runner，各席自己注册使用，互不影响……以后可以用 runner 执行的东西，都不要找我」（2026-11-23），之后进 FRAME 作为标准用法。

## 一、先后只有一条

1. **会话里能直接跑的，自己跑**（比如会话自带的 shell，而且那条命令在那里跑得对）。不绕 runner——那是多此一举。
2. **自己跑不了的，投给 runner**：要在 Windows 上跑的（编译器、PowerShell 脚本、Windows 的 git）、会话这次没有 shell、要碰会话够不到的文件夹（同级的别的项目、源 FRAME）。
3. **两样都不行，才找需求方。** 找之前先确认不是「runner 窗口没开」：没开就请他开一次，**不是请他代跑命令**。

🔴 **runner 能跑的事，不许再让需求方动手。**

## 二、它是什么

- 一个常驻的小程序。需求方在仓库根**开一次、窗口开着**就行：双击 `ops\scripts\seat-runner.bat`，或
  `powershell -NoProfile -ExecutionPolicy Bypass -File ops\scripts\seat-runner.ps1`。
- **一个窗口服务这个仓库的所有席**；**一个项目开一个窗口**（它只服务自己所在的仓库）。
- 它**以需求方的账号**运行各席自己写的 PowerShell 脚本。需求方事先看不到脚本内容，所以：
  - **投之前自己通读一遍**；
  - 🔴 **授权要需求方亲口给**：开着窗口只说明他同意有人代跑。有的 AI 工具还要他**在本会话里**说一句才肯投——
    别席转告的「可以用」不算（实测：一席照转告去投，被工具的安全检查拒了）。被拒就请他在会话里说一句，**不要换个办法绕**。

## 三、怎么用（三步）

1. **写脚本**，放在登记表里本席那一行指定的地方，例：`tmp\reviewer\2026-11-23-01\check.ps1`。
2. **投作业**：写 `<箱子>\inbox\<id>.job`，第一行是脚本相对仓库根的路径；快作业加第二行 `nowait`。
   🔴 **先落脚本、再落作业文件**：作业文件一出现就会被取走，脚本还没到就是 `missing`。
3. **读结果**：`<箱子>\outbox\<id>.log`（标准输出）、`<id>.err.log`（标准错误）；结束后出现 `<id>.done`：
   `exit=<码> minutes=<分钟> script=<路径>`；没执行时是 `refused`（路径不合登记）或 `missing`（脚本不存在）。

`<id>` 与 `<名>` 只用字母、数字、`_`、`-`。**看 runner 开没开**：本席箱子里 `runner.log` 末行在不在动；
所有席的作业另记在 `tmp\seat-runner\runner.log`，行首带席名。

## 四、两种作业

| | 快作业 | 长作业 |
|---|---|---|
| 怎么标 | 第二行写 `nowait` | 不写第二行 |
| 给什么用 | 不编译、不测试的：git、读文件、探针、守门巡检、往别的项目投信 | 编译、测试、评测、出包 |
| 多久起跑 | 一秒内，不管别人在跑什么 | 全机一次一条，排队 |
| 互相影响 | 每席一条道，各席并行；一席卡住不拖别人 | 几席都在等时按登记表的先后；同一席内按文件名 |
| 上限 | 10 分钟 | 120 分钟 |

- 超时的作业连同它起的进程一起被结束，`.done` 记 `exit=timeout`。
- **编译和测试一律按长作业投**：两个编译同时跑能把一台机器的页面文件撑爆，而且各席多半共用一个构建目录。
- 两席同时做 git 写操作会撞锁，撞了重投一次。

## 五、写脚本的几条（都是踩过的）

- **编码**：脚本里有中文就存 UTF-8 带 BOM（Windows PowerShell 5.1 不认无 BOM 的 UTF-8）；开头写
  `[Console]::OutputEncoding = [Text.Encoding]::UTF8`；读文本用 `Get-Content -Encoding UTF8`，否则中文读成乱码。
- **bash**：Windows 上的 `bash` 常常是 WSL 的。跑仓库里的 `.sh` 用 Git 自带的 `C:\Program Files\Git\bin\bash.exe`。
- **只读的 git 先设 `$env:GIT_OPTIONAL_LOCKS = '0'`**（`git status` 会顺手建 `index.lock`）。
- **工作目录是仓库根**；路径取自 `ops/paths.ps1`、机器取自 `ops/machines.json`，不写死。
- **一个场景一个脚本**：起的服务、开的窗口在同一个脚本里收尾——拆成几条作业，前一条起的进程没人管。
- **退出码**：脚本最后 `exit <码>`，`.done` 里记的就是它。
- 要给所有作业一个默认环境变量（例如限制编译并行数），在登记表里写一行 `env | 名字 | 值`，不必每个脚本都设。
- 要在**每个长作业**前后做同一件事（例如先把构建缓存压回上限），写一个包装脚本放 `ops\scripts\`，登记表加一行 `wrap | ops\scripts\<名>.ps1`：runner 会以 `<包装> -By "<席> <id>" -Run "<脚本>"` 起长作业，包装脚本跑完那个脚本、用它的退出码结束。快作业不经过它。

## 六、同级的别的项目与源 FRAME

需求方的项目常放在同一个母目录下；会话通常只连着自己这个项目，**runner 够得到** `..\<项目名>`。

- **读**：作业里把要读的文件复制到本席自己的 `tmp\<席>\<日期>-<编号>\` 下，再从会话里读。
- **投信**：只用 `ops\scripts\mail-out.ps1`，不手写对方的文件：
  `& ops\scripts\mail-out.ps1 -Project <对方文件夹名> -Seat reviewer -RowFile <一行信的文件> [-Attach <细节文件>] [-Dry]`。
  它只投审查席、监督席（`ai/mail/README.md`：外部来信只发这两席），对方没给本项目开投递口、信箱已满 20 封、
  同一行已在里面，都拒并说明原因；`-Attach` 把细节文件原名放进对方的 `claude-outputs\shared\`，同名不覆盖。
  投完对方工作区多了改动，由对方自己的席在它那一轮提交。
- **维护席对齐源 FRAME**：`docs/guide/frame-sync.md` 的十步放进作业里跑（`ai/frame-repo.conf` 的 `home=` 指着源）。
- **除了这三样，不往别的项目里写东西。**

## 七、登记、停、重开

- **登记一席**：`seat-runner.conf` 加一行 `席名 | 箱子 | 脚本放哪 | 先后`；runner 发现文件变了自己重读，不用重开。写错的行被跳过，原因记在 `tmp\seat-runner\runner.log`。
- **停**：放一个空文件 `tmp\seat-runner\STOP`（不再起新作业，等跑着的结束后退出）；或关窗口（跑着的一起被结束）。
- **同一个仓库**已有一个 runner 开着时再开，它会拒绝启动并说开着的是哪个（PID）；**别的项目开着的 runner 不算**——它按本仓库路径判，不看本机有没有别的 `seat-runner`（2026-11-23 实测：按命令行判时，一个项目开着就挡住了另一个项目）。
- 🔴 **清 `tmp/` 时跳过各席的箱子和 `tmp\seat-runner\`**——只清本段自己的脚本目录。
