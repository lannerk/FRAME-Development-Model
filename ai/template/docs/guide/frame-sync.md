# 口令「同步 FRAME」—— 维护席照这一份走

> **谁读这一份**：维护席，收到口令「同步 FRAME」的那一刻。
> 机制与判据写在脚本头部 `ops/frame/frame-sync.sh`；分类表 `ops/frame/classes.txt`；本仓库画像 `ai/frame-repo.conf`。

## 一、它要保的那件事

**任何 FRAME 项目都能和源仓库对齐，而两边谁都不丢东西。**
本项目没改过 FRAME 时，同一套规则跑出来自然就是**单向从源拉回**——「单向」不是一种模式，是双向的自然结果。

| | 给谁看 | 怎么来 |
|---|---|---|
| **fingerprint** | 🔴 **给机器判**：两边是不是同一套 FRAME | 所有 `follow` 类内容的聚合哈希，**自动算，别手改** |
| **version** | 给人看：这套 FRAME 是第几版 | 🔴 **维护席 bump**：结构/角色变 = major · 规矩语义变 = minor · 措辞 = patch |

## 二、十步（口令背后就是这个）

1. 本项目的 FRAME 干净吗？脏 → **拒绝**，先提交（🔴 **只认已提交的 FRAME**）。
2. `bash ops/frame/frame-sync.sh --status`：算本项目指纹、读版本号。
3. 从 `ai/frame-repo.conf` 的 `home=` 找到源，算它的指纹与版本。
4. **指纹相同 → 回「已是最新」，一个文件都不动，结束。**
5. `--sync`：三方合并出**拉回 / 推出 / 🔴 要人处理**三张清单。
6. 有要人处理的 → **只报不改**，给出 `--diff` 命令，结束（人处理完再喊一次口令）。
7. 没有 → 把报告给需求方看 → 他确认 → `--sync --apply` 两个方向一起写。
8. 重算两边指纹（应当相同）→ **维护席 bump 版本** → 两边各写 `ai/FRAME-VERSION`。
9. 重记基线（`--apply` 自动做）；两边 `ai/rules/maintenance-log.md` 各记一行。
10. 🔴 源那边的改动**提交并推 GitHub**（它是开源仓库）。

## 三、🔴 首次同步：没有基线，必然全是「要人处理」

三方合并靠基线分辨「谁改的」，**第一次没有基线就分不清**——这是**原理性的，不是实现缺陷**。两条路：

- `--diff` 逐份看过，人工判方向；
- 或确认某一边就是对的，`--adopt` 把现状收为基线。🔴 **adopt 等于承认现状是对的，先看过再认。**

**记账要写清你走的是哪一条。**

## 四、别把这几处改「顺手」了

| 别动 | 原因 |
|---|---|
| 把默认改成 `follow` | 漏分类一条就**静默丢东西**；默认 `seed` 时漏一条只是「被创建」 |
| 让 `seed` 参与双向覆盖 | `CLAUDE.md`、各 `index.md`、`memory.md`、`inbox.md` 项目里填过内容，**推回源会把项目内容带进 FRAME** |
| 自动删除目标文件 | 删除不可逆。🔴 **一边删了只报告**——把「被删」当成「新增」推回去，会让人**永远删不掉那个文件**（实测过） |
| 用 mtime 代替内容指纹 | `check-template-sync` v1 就栽在这（新克隆报 11 份假红，实际一份没改） |
| 手工去改开源仓库那几份根文件 | 它们是**模板 ＋ 声明式补丁**（conf 里的 `map=` / `patch=`）；手工改完下次同步会判成「目标改过」而报冲突 |

## 五、开源用户：只从源拉回（`role=consumer` ＋ `push=no`）

> 谁读这一段：**从 GitHub 拿这套 FRAME 开自己项目的人**。你没有源仓库的提交权，
> 所以同步只有一个方向：**源 → 你的项目**。这不是另一套机制，是同一套加一行 `push=no`。

**装配（一次性，三步）**

1）把源仓库克隆到**你的项目的同级目录**：

```
cd <你的项目的上一层>
git clone https://github.com/<源仓库>/FRAME-Development-Model.git
# 结果：  上一层/你的项目/        上一层/FRAME-Development-Model/
```

2）填你项目里的 `ai/frame-repo.conf`，三行就够：

```
role=consumer
home=../FRAME-Development-Model
push=no
```

- `home=` 写**相对你的项目根**的路径就行（换一台机器、换一个盘都不用改）；写绝对路径也认。
- 🔴 `push=no` 是这一段的关键。不写它，同步会把你本地对 FRAME 的改动**往源仓库里写**——
  你没有提交权，推不上去，结果只是把源仓库的工作区搞脏，而你以为同步成功了。
- 🔴 **项目是从英文模板起的，每条命令前面都要加 `FRAME_TEMPLATE=ai/template-en`**：
  它决定和源仓库的哪一份模板对账。不加就去跟中文那份比（实测 42 份假冲突）。

3）立第一份基线：`bash ops/frame/frame-sync.sh --adopt-mine`

🔴 **是 `--adopt-mine`，不是 `--adopt`**：基线记谁的，决定了以后所有差异算谁的（§三）。
记**你自己现在这样** ⇒ 以后源那边的变化都算「源改的」⇒ 下一轮**拉回来**；
记成源那边，你会看到「你改了 21 份」——而其实是你落后了 21 份，方向正好反。
🔴 立基线之前，先 `--diff` 把报成「没有基线」的那几份看一眼：**你自己动过的那几份，
adopt-mine 之后下一轮会被源那份盖回去**。先按下面那条把它们挪成新文件。

**一个源仓库，几个项目**

源仓库**克隆一份就够**。你有几个基于 FRAME 的项目，就在**每个项目**里各填一份
`ai/frame-repo.conf`（都指向那一份克隆）＋各立一份基线，以后**一个项目跑一次同步**。
🔴 `home=../FRAME-Development-Model` 这种相对写法要求**源与项目同级**；
不同级就写绝对路径（`home=D:\code\FRAME-Development-Model`），一样认。

**🔴 为什么源仓库维护者那边是 `push=yes`、你这边是 `push=no`，却不用任何开关**

`ai/frame-repo.conf` 是**每个仓库自己一份**，而且在 `ops/frame/classes.txt` 的 **skip** 名单里——
**同步永远不碰它**。所以维护者那份 `yes` 传不到你这儿，你那份 `no` 也传不回去；
模板里发出去的样板写的本来就是 `role=consumer` ＋ `push=no`。
不写那一行时**按角色定**：`consumer` 默认 `no`，`home`/`host` 默认 `yes`——
**默认值要让漏填的那一方安全**。自己就是源仓库维护者的项目，显式写 `push=yes`（显式永远压过默认）。

**以后每次跟进（四条命令）**

```
cd ../FRAME-Development-Model && git pull && cd -   # 🔴 pull 在源那边跑：它和你的项目是两个仓库
bash ops/frame/frame-sync.sh --sync                 # 只报不改，先看报告
bash ops/frame/frame-sync.sh --sync --apply         # 看懂了再写
bash ops/verify/check-all.sh                        # 规矩变了，守门也跟着变了
```

收尾三件：`--stamp <源那边的版本号>`（`push=no` 时只写你这一份）· `ai/rules/maintenance-log.md` 记一行 ·
跟你的 AI 说一句「重载规范」。

**🔴 你自己的补充写成新文件，别改 FRAME 自带的那几份**

新文件上游没有，机制会认出「**本项目自己加的**」，报告里数一笔，**永远不管它**——
加一份 `ai/rules/ours-xxx.md`，比改 `ai/rules/workflow.md` 省下以后每一轮的事。
真改了自带的那几份，每轮都会看到一次 🔶「本地改过 FRAME，不推上游」，三条路：
**留成分叉**（基线记的是**上游那份**，所以它不会被悄悄盖掉；上游以后也改了这一份，就升级成 🔴 要人处理）·
**放弃本地改法**（把那份删掉，下一轮自动拉回）· **去源仓库提 issue / PR**（这套机制不替你推）。

**怎么判断自己是不是最新的**

| 看哪儿 | 怎么读 |
|---|---|
| `--sync` 头两行的**指纹** | 🔴 **消费者不能这样比**：指纹只在**同角色**之间可比（`follow@home` 那几份对你根本不是 follow），所以你和源的指纹**天生不同**。你的判据是报告末尾那句「✅ 和上游一致」 |
| `ai/FRAME-VERSION` 里的 `source_fingerprint` | 它记的是「上次同步时**源那边自己的**指纹」。和源仓库 `ai/FRAME-VERSION` 里的 `fingerprint` 一致 = 你跟上了。`version` 是给人看的版本号，`--stamp` 抄过来 |
