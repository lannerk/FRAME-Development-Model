# Domain practice: platform / operating system / device products

| Dimension | What to do | Why |
|---|---|---|
| The product line | One brand, several lines: the full form factor · the light form factor · multi-platform clients (whose reason to exist is connecting several devices) · the cloud (site · store · accounts · developer platform · public API · remote control plane) · the admin console | Draw the whole picture first, or you will not know what has to be shared |
| Full and light | One product in two form factors: shared kernel, app protocol, SDK, interface and permission table; platform differences collected in a Provider layer, **cut by capability**, with no generic Linux adaptation layer | A generic adaptation layer shaves the full form factor down to the lowest common denominator |
| Architectures and images | App developers should barely think about CPU architecture; images are built per architecture; the light form factor does arm64 and x86_64 only | Testing 32-bit and exotic architectures costs far more than it returns |
| Sequencing | Phase one: the system itself + every built-in app + extensibility; after that **order by technical dependency** (light form factor → clients and remote → cloud / console) | Ordering by dependency means never going back to build the base half way through |
| Remote access | P2P direct connection first; users can run their own relay; the official fallback relay is strictly rate-limited and says so in the UI; addressing carries a device id from day one (`<scheme>://<device>/<app>/<resource>`) | Data does not pass through us, and adding devices later does not change the URLs |
| Licence activation | A licence is a signed document; three activation paths (online / offline / remote); licensing and permissions are two separate sets of fields | An offline device still has to be able to activate |
| Error collection | Let the user choose whether to report; the server aggregates and replies automatically; defects flow straight into the development queue; user reports and defects are separately permissioned | Production problems have to reach the development loop |
| Debug channel | Local maintenance and development have a standard maintenance and debug channel that AI can push to, verify against and test on | What AI lacks most while building is "being able to verify on the real machine" |
| System baseline | A rollback-capable filesystem (snapshots), signed package sources, an automatic snapshot before upgrading; Wayland | A failed upgrade is one step from being undone |
| Processes and security | Kernel processes do not run as root; privilege goes only through a **typed-action** privileged helper (never a generic exec); an agent per user; each app in its own sandbox speaking only over a unix socket | One exec hole is the whole machine |
| State | The truth lives in the kernel; global state sync (list first, then watch, with version numbers); one event connection per client, resumable | Several interfaces and several devices see one truth |
| Professional apps (reserved) | Reserve the lower layers that video editing and its kind need: GPU encode/decode, streaming large files, long render jobs, professional components | Adding them later then needs no kernel change |
| DevOps (reserved) | CI/CD against various git hosts; a server console (deploying apps, one outbound entry point, domains and automatic certificate renewal); packaging and builds in their own sandbox | The platform is itself a developer's workbench |
| Home / device ecosystem (later) | First the hub that "sees" the most → a device domain abstraction → a standard-protocol controller (such as a Matter controller) → device identity PKI → voice endpoints plus the hub brain → a certification programme; **no protocol or brand names in the domain layer** | Protocols get replaced, domains do not |
| The boundary | Write down which categories you will not do (no phone OS, no TV OS, for instance) | Platform products are the easiest to be dragged into expanding |
| The irreversible list | Before any code: the process model, the state model, addressing, licensing, the style contract, the filesystem … each ruled on | Platform products have an unusual number of irreversible decisions |
