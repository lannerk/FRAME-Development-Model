# 术语表 —— **机器也在读的词**

> **翻译这套文档之前先读这一份。** 见 `docs/guide/project-init.md` 第 2 步。
>
> 这里列的词有两种命运：**译了要同轮改脚本**，或者**根本不许译**。
> 搞错了的后果是**守门静默失效**——脚本照常 exit 0，但它其实什么都没在看。
> **这种坏法没有任何症状**，所以才要有这一份。

## 一、**不许译**（一个字都不许动）

| 词 | 在哪 | 为什么 |
|---|---|---|
| `BUILD-OK` `INBOX-OK` `CHECK-PATHS-OK` `TEMPLATE-SYNC-OK` 及各自的 `-FAIL` | 守门脚本的输出 | **脚本之间、脚本与人之间靠这个字符串对接**，译了就断 |
| `T-####` `AD####` | 任务号 / 决策号 | 机器和人都按它检索 |
| 所有目录名、文件名 | 整个仓库 | 结构要跨语言通用 |
| 代码、变量名、JSON 的 key、配置项、命令 | `.sh` `.ps1` `.json` | 它们是代码不是文案 |
| `P0` `P1` `P2` `P3` `P4` | 优先级 | 短、无歧义、跨语言通用 |

> 脚本里**注释和 `echo` 给人看的那句话可以译**——但**不要碰引号里那几个标记词**。

## 二、**译了必须同轮改脚本**

| 词 | 谁在读它 | 译的时候要改哪里 |
|---|---|---|
| `待处理`（收件簿状态） | `ops/verify/check-inbox.sh` 里的 `grep` | 把脚本里的那个词一起换成译文 |
| `待实施` `开发中` `待审` `已过` `挂起` `作废`（任务状态） | 目前只有人在读；一旦你加了「按状态统计」的脚本，它就进这一类 | 同上；并在这张表里补一行 |
| `待处理` `已转任务` `已答复` `不做`（收件簿处置） | 同上 | 同上 |

**改完必须验**：故意造一行「未处理」的记录，跑 `bash ops/verify/check-inbox.sh`，
**它必须红**；删掉再跑，必须绿。**两个方向都试过才算改对**——
只看到绿的那一半，等于什么都没验。

## 三、译名要**从一而终**

同一个词在整套文档里只能有一个译法。定下来之后补进下面这张表，
下一个人（或下一个会话）照着它译，**不要每份文档各译各的**。

| 原词 | 你的译法 |
|---|---|
| 需求方 | |

| 审查席 / 审查者 | |
| 监督席 / 监督者 | |
| 维护席 / 维护者 | |
| 依据 | |
| 守门（脚本） | |
| 反向断言 | |

## 四、加新词的时候

**你往守门脚本里写死了一个中文词**，就回来在第二节加一行。
不加的代价是：下一个项目换语言时把它译了，**守门从此形同虚设，而没有人会发现**。
