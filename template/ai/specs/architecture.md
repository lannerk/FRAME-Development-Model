# 系统架构

> **这一份是架构的唯一真相。** `docs/architecture.md` 只留一页导读指过来，**不要两边各写一套**。
> 改架构**一律另记一条 AD**——它是别人做决定的地基，地基换了没人通知，塌的是上面所有东西。

## 一、整体形状
一张图或一段话说清：有哪几块、各自负责什么、谁调谁。

## 二、每一块是什么
| 组件 | 干什么 | 跑在哪 | 不归它管的 |
|---|---|---|---|
| | | | |

## 三、边界与入口
对外唯一入口是什么、鉴权在哪一层、哪些面不对外。**写清 fail-open 还是 fail-closed。**

## 四、不能碰的前提
违反了就会出事的那几条（带 AD 编号）。

## 五、明确不做的
排除掉的架构选项 + 为什么。**这一节比上面几节更省事**——它挡住「要不要改成 X」的重复讨论。
