# BUG 台账

> **一个 bug 一个文件**：`ai/bugs/B-####-<一句话>.md`。这张表只放索引，细节在文件里。
> **已关闭的那几行就是「修过的 bug 清单」**——回归测试每轮重跑它们（`ai/specs/testing.md` §7）。

**下一个可用编号：B-0001**（用了就把这行加一）

## 状态

```
待复现 ──复现成功──▶ 已复现 ──开任务──▶ 待修 ──开发回报──▶ 修复待复测 ──审查复测──▶ 已关闭
   │                                                              │
   └──复现不了──▶ 无法复现（回去问需求方要条件，不是丢掉）         └──复测没过──▶ 待修
```

旁支：`不修`（写明为什么 + 谁拍的板）。

**三条不许**：

- **复现四件没写全，不许转给开发**（环境 / 前置条件 / 步骤 / 现象）。让开发去猜复现步骤，
  猜错了修的就是另一个问题。
- **开发不许自己把 bug 标 `已关闭`。** 他能推到 `修复待复测`，**关闭权在审查席**——
  自己修的人测不出自己的盲区。
- **`修复待复测` 不许过夜到下一轮。** 开发回报里只要有「修了 bug」，
  **审查席本轮必须复测**，不需要需求方说「审查并测试」。

## 严重度

| 级 | 什么 |
|---|---|
| **S1** | 阻断：整块功能用不了 / 数据会丢 / 提权 |
| **S2** | 严重：主流程能走但结果错，或每次都出 |
| **S3** | 一般：偶发、有绕法 |
| **S4** | 轻微：观感、文案、边角 |
