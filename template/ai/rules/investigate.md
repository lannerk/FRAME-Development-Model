# 怎么查一个「坏了」—— **头一小时手册**

> **谁读这一份**：**拿到一条 bug、或者被要求定位一个问题的那一席**——
> **开发席和审查席都要读**（开发要还原问题、查自己改出来的坑；审查要查案、判过不过）。
> 监督席做专题盘查时同样适用。
>
> **为什么单独一份**：这是**通用方法**，不属于任何一个席位。
> 它原本写在 `ai/roles/reviewer.md` 里，需求方指出「开发者有时也需要调试问题、还原问题」——
> 通用的东西放进某一席的手册，另外几席就读不到（`ai/rules/layout.md`「谁能改规矩」那一节同理）。
>
> **什么时候读**：**拿到「坏了」的那一刻，动手之前。** 不是开场读，是用到就读——
> 一页，五步，读完再开口。

> **这是这套规范里唯一讲「怎么查案」的一份。** 监督席实测过：在它出现之前，
> 开场必读近六百行里「排除树 / 证伪 / 前置断言」的命中数是 **0**——
> 会话读到什么就做什么，于是**默认去记账、去传球，而不是去查**。

**这一轮的主线是「查清楚」，不是「记齐全」。** 收件簿照规矩当轮一句一行记（这条不许省），
**其余记账类工作（复盘、方案、台账整理）一律延后**——他等的是「这到底怎么回事」，不是一份格式完整的档案。

### 1. 把现象拆成**能判真假**的句子，并标出它属于哪一层

「整个浏览器不动」和「页面请求一直转圈」**不是一句话**——前者是浏览器主线程，后者是网络连接。
**不同层、不同探针、不同根因。**
**判据**：现象节里不许留「卡死 / 不正常 / 有问题」这种判不了真假的词。

**开 B 号之前，拿现象里的关键词在 `ai/decisions/` 和 `claude-outputs/` 各 `grep` 一次**——
两条命令，能避免把别人已经查过的路再走一遍。

### 2. 最小复现环境三问（按顺序，答到「能」就停）

| 问 | 能的话怎么做 |
|---|---|
| ① 纯前端（HTML / CSS / SVG / JS）？ | **容器里起 http 服务跑真页面**，不要真机、不要登录（`file://` 会把 sprite 的 fetch 拦掉） |
| ② 纯函数 / 协议 / 配置解析？ | 直接在容器里跑 |
| ③ 真的必须真机？ | **写清「必须的是它的哪一件」**：某进程的运行态 / 某块硬件 / 某份线上数据 |

**判据**：bug 文件「定位」节第一行必须是这三个答案之一。**不许写「够不到」**——那是铁律 7 管的（见下）。

### 3. 画排除树

至少两个分支，每支写【怎么判掉 · 要多久 · 结果】。**没有树，不许写「根因」。**

### 4. 成本升序执行，**第一刀必须是 ≤1 分钟、零命令的那一刀**

换窗口 / 无痕 / 强刷 / 换账号 / 换端口 / 换个小文件。
**判据**：第一个被执行的分支成本不是最低的，要写明为什么。
**真事**：「换个浏览器窗口打同一个地址」这一刀，排在了读 Go 源码、猜磁盘、猜时区之后，
等需求方第三次追问才切——**它一切就当场定案（200 / 13ms）**。

### 5. 三个词分级（详见下面「三个词分级，不许混用」）

**排除树全部分支有结果，才许写「结论」。**

## 三件手法，与麻烦需求方的门槛

### 三件手法

- **前置断言**：任何复现台，**先证明台子真的进到了你要测的状态**。
  前置断言不绿，后面所有「没复现」都只是空窗口。
- **证据要在和用户同一前提下取**：DPR、浏览器、登录态、缩放、窗口宽度。
  比大小必须**同比例、同尺寸裁框**，不许并排看两张不同宽度的渲染图。
- **能穷举就别猜。** 穷举一次的成本，通常低于猜三次。
- 🔴 **有测试断言 ≠ 有意为之。** 看到 `xxx_test.go` 断言了当前行为，**只能证明「有人写过它」，不能证明「它对」**。
  要判**那条断言保的是不是用户要的那件事**：断言锁住的往往是**实现细节**（某个字段有没有被改动），
  而要保的是**用户看到的东西是不是真的**。这就是 AD534/537/538「判要保的那件事，别判它的文本影子」，
  **只不过影子这次长在单元测试里**（审查席 2026-09-16 实测：因为 `jobplan_test.go:87` 断言了当前行为，
  把一条真 bug 判成「既定行为、要需求方拍板」，连错两轮）。
  **判法**：先说出这条断言在保什么、用户要的是什么，两者不是同一件事时，**断言本身就是 bug 的一部分**。

### 麻烦需求方的门槛（铁律 5 的可执行版）

1. **开口之前先自证做不到**——贴铁律 7 那张「我试过哪几条路」的三行表。**列不出三行，不许开口。**
2. **一轮只能有一份步骤单**：编号 · 每步一行命令 · 每步贴回什么 · 共几分钟 ·
   末尾「**全部贴完我再回复**」。同一轮出现第二份 → 违规，写进审查记录。
3. **绕法不算交付**（见 `ai/bugs/README.md`）。

### 「我做不到」也是否定性结论（铁律 7 的判据）

**「我够不到 / 必须上真机 / 我还没想到办法 / 得你帮我跑」——这些全是否定性结论。**
说之前先把**试过哪几条路**摆出来：

| 试过的通道 | 结果 | 证据 |
|---|---|---|
| 容器 / 沙箱里能不能直接跑 | 能 / 不能 | 命令 + 输出 |
| 只读探测（浏览器、HTTP 接口） | 能 / 不能 | 响应或截图 |
| **源码里有没有同样的信息** | 有 / 没有 | 文件:行号 |

**列不出这三行，就不许说做不到。**
**真事**：技能清单那条说「还没想到不用 shell 的办法」，而 `grep` 三分钟就能在源码里找到那个 GET 接口——**没碰真机**。

### 反向断言的两句话，第一句常被漏掉

反向断言要证明的是**两件事，顺序不能反**：

1. **这条路径在这一格里真的会被走到**；
2. 把它改坏，这一格会红。

**只做第 2 句，这一格可能从头到尾没执行到被测代码**——它红是因为别的原因，或者不红是因为压根没走到。
**「跑了一格反向断言」是文本影子；「这一格真的走到了被测代码并且红了」才是那件事。**

**两种已实测到的失效**（开发席 2026-09-16 自己诊断出来的，两轮各一个变种）：

| 变种 | 形状 | 咬住的其实是 |
|---|---|---|
| 甲 | 造的错让程序**跑不起来**（编译错／语法错） | **编译器**，不是被测逻辑 |
| 乙 | 造的错造在**这一格走不到的分支**上（原话：「造错了但没造在会出事的那一步上」） | 什么都没咬住——**断言的前置条件没满足** |

**判据三句，写进反向断言实录里，缺一条不算做过**：

- 这一格触发被测代码的**前置条件**是什么、怎么满足的；
- 改坏之后的红，**红在被测的那个断言上**，不是编译器、不是别的断言；
- **改回来之后绿。**

> **为什么这条值钱**：反向断言是整套守门里**唯一**能证明「这一格真的在咬东西」的手段。
> 它一旦空转，就回到了「有用例＝有保障」的幻觉，**而且比没有用例更糟——它给人已经验过的错觉**。

## 三个词分级，不许混用

**假设**＝没有证据的想法，**必须同时写「用什么动作证伪、要多久」**，**只能出现在排除树里**；
**实测**＝有命令输出 / 截图 / 数字 / 请求响应；**结论**＝排除树**所有分支都有结果**之后才能写。

**给需求方的回话和任何台账里，只许出现「实测」和「结论」。**
一个不断自我推翻的「结论」，对他的价值是负的。
**判据**：出现「收回 / 作废 / 我前面的结论不成立」，**必须同时写清当初是靠什么下的那个结论**；
同一轮出现两次以上 → 那一轮的结论降级为「未定」。
