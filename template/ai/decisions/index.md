## 按编号段分文件

| 文件 | 装什么 |
|---|---|
| `AD0001-0100.md` | AD1 ~ AD100 |
| `AD0101-0200.md` | AD101 ~ AD200 |
| `AD0201-0300.md` | AD201 ~ AD300 |
| `AD0301-0400.md` | AD301 ~ AD400 |
| …… | 用到哪个建哪个 |

**为什么按编号段而不按主题**：编号有序，**拆分可以机器校验**——不可能漏、不可能重、不需要任何判断。
实测过按主题自动归类：绝大多数条目会命中多个主题，还有一批一个都不命中，最后还是要人逐条判断。
**分文件的目的是「别为看一条读整本台账」，编号段已经完全解决**；要按主题看，用下面的标签 `grep`。
号段文件用到哪个建哪个，不用一次建七个。

## 主题标签（每条都有，用来 grep）

| 标签 | 范围 |
|---|---|
| `网络` | 网络相关 |
| `<标签>` | `<按你的项目分，八个以内>` |




| `硬件` | 硬件与外设（没有就删掉这一行） |
| `流程` | 铁律、三角色、文档体系、台账自身的规矩 |

**一条只打一个标签**——打它「主要改动落在哪」的那个。要找跨主题的用 `grep -E '网络|系统'`。

```
grep -h '| 网络 |' AD*.md          # 所有网络相关
grep -h 'AD42' AD0001-0100.md      # 查一条
```

## 统一表头

```
| 编号 | 主题 | 决定了什么 | 决策状态 | 实现 | 详情 |
```

- **决定了什么**：一句话，**≤60 字**，写「定了什么」不写「为什么」。为什么在详情里。
- **决策状态**：`✅需求方拍板` / `✅审查代拍` / `⏳待定` / `🗑已覆盖（被 ADxxx 取代）`
- **实现**：`已落地` / `已落地·真机验过（第N段）` / `部分（做了X，Y 在 T-####）` / `待开发` / `不做`
  **每段收尾必须改这一列**（`../rules/conventions.md` 8）。多子项的总纲行不写进度，写「子项散在各任务」。
- **详情**：`归档` ＝ 去 `archive/` 搜编号；也可填 `../specs/xxx.md` 或 `../tasks/T-####-*.md`。

## 怎么加一条

1. 从上面取号，**立刻加一**；
2. 在**它所属号段的文件**表尾追加一行（编号本身就是顺序，不要插中间）；
3. **长叙述不要写进表格**——写进关联的任务或方案，表格里填指路。
   台账是「定了什么」的清单，不是事故报告。旧台账一条 2000 字，是它涨到 738KB 的直接原因。
