# 项目记忆 —— 交代过一次、以后都算数的事

> **开场必读的一份，所以必须短（上限 80 行）。** 规范管「怎么协作」，`docs/` 管「流程与细节」，
> **这一份只管下面七样**。**四席都读，四席都能写**（规矩只有维护席能改，**记忆谁都能记**）：
> 需求方交代了一件项目性的事，**当轮记进来，回他一句「已记进项目记忆」**。
> **记不记由这一席自己定，不用问需求方拍板**——记忆是记录，不是决策（他 2026-09-15 原话：「项目的记忆是角色自己决定是否记录的，不需要问我」）。**要改规矩才要经维护席。**

## 只记这七样

| # | 记什么 | 写成什么样 |
|---|---|---|
| **1** | **经常要用的必要信息** | 运维页面地址 · 进去用**哪一个** token、**去哪找** · 服务真正的单元名与端口 · 哪台机器不能重启 |
| **2** | **特定情况按特定方式处理** | 「遇到 **X** → 就按 **Y** 办」＋一句为什么 |
| **3** | **自己摸索出来的解法** | 「**我这次是用 Z 解决的**，下次同样的事照 Z 办」——**记它就是为了下次不用再绕一圈** |
| **4** | **踩过的错法（查证过的）** | 「**这样写是错的：…… 正确是：……**」。需求方原话：「**错误的做法查证后记住，以后类似不要再犯同样的错**」。**一个人踩过，四席都不再踩** |
| **5** | **他的偏好与红线** | 要什么格式 · 什么时候别打扰他 · **哪些事必须他本人做**（贴 key / 密码 / 登录）· 他明确讨厌的做法。**新会话最容易丢的就是这一类，丢了他就要重新教一遍** |
| **6** | **环境与平台的怪癖** | 非文档化的事实：挂载盘不区分大小写 · 某平台把网页终端打字判成远程执行而拦下 · 云端容器 curl 真机 403。**不是错法（类型 4），是「这里就是这样」** |
| **7** | **术语对照** | 他口里的词 ↔ 实际的模块 / 文件 / 服务。**误解他的术语不会报错，只会体现为交付跑偏** |

**每条都要带「哪天验的」**（和分层探针表同一条道理）：**token 的位置会变、平台策略会改**，
三个月后没人知道那条还成不成立。**没有日期的条目，下一个人不敢信也不敢删。**

**来源两种**：①他告诉过你的（类型 1、2）；②**你自己摸出来的**（类型 3、4、6）——后者最容易丢，
**绕了一圈才找到的办法不记下来，下次还要再绕一圈**。

## 不记这些

需求方原话：**「如果这些记忆和规范重复，那就没必要记住。」** 同理不记：
**开发细节与流程步骤**（规范和 `docs/` 已经记着，这里最多留一行指路）· **凭据本身**（见下 🔴）·
**「现在做到哪了」**（`now.md`）· **「当初为什么这么定」与「提过但被否掉的方案」**（都在 `ai/decisions/`，AD 本来就有「否掉了什么」那一列）· 只发生一次、**换个场景不会再犯**的意外（会再犯的错法属于类型 4，要记）。
**满了就把成段的挪进 `docs/`，只留一行指路——这一份的价值在于短。**

## 一个正好在边界上的例子

「测试机在哪、怎么上传东西」这一句里有三样，**分别归三处，别重复**：
机器是哪台、地址多少 → **`ops/machines.json`**（唯一出处，文档按 `id` 引）；
上传的**步骤** → **`docs/ops/`**；**进去用哪一个 token、去哪找、粘到哪个框** → **这一份**。

**这就是判据的样子**：重复的不记，**规矩管不着、又每次都要用的那一点点才记**。
**上面提到的都是例子，不是清单**——判据是那三类，不是这几件事。

## 🔴 凭据本身不许落盘

**记「哪个 token、在哪找、粘到哪里」，不记它的值。** 值由**需求方本人粘贴**（铁律 5 的红线）。

**唯一的例外：需求方点名豁免的那台机器。** 他拍板「这一台的凭据就放仓库里、随 git 走」时，**照他说的办，把「他豁免过」连原话记进第一节**——**不许再挪、不许再问他要**（2026-09-16 原话：「这个令牌无所谓……**以后任何人不许再问我拿令牌，除非开发机换了或增加**」；开发席按原规矩挪去 `tmp/`，结果一次又一次回头问他要）。**例外只覆盖被点名的那台机器**：换机器、加机器、生产环境，红线照旧。
写成这样才对：「运维页面 `<地址>` 上传要『上传令牌』，它在 `<哪里>`；**需求方本人粘贴，AI 不留存**。」
